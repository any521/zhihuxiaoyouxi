## 1. 舞台与世界观

### 1.1 基本设定

- **公司**：一家做内容的互联网公司，不是大厂。部门叫「看山创意部」，包含刘看山在内共 6 人。
- **玩家**：刘看山，实习生。三个月，跨 90 天，10 个关键节点（事件 `day` 字段为 1/3/8/15/32/40/55/64/76/90）。
- **项目**：一个**校园联名**项目。客户方对接人是程女士。三个月里，它从一句模糊要求走到签约。
- **三章结构**：第一月＝摸清规则与人；第二月＝做出东西并被推翻；第三月＝交付、归属、答辩。
- **空间**：工位区、会议室 A、前台、楼下咖啡、地铁口。这些是**场景描述**，不新增界面。

### 1.2 世界一直在发生的事（暗线，智能体演绎时必须记得）

| 暗线 | 第一次出现 | 推进 | 收束 |
|---|---|---|---|
| **版本地狱** | 事件 1：韩策发来 `项目排期_v4.xlsx` | 事件 6：三个"最终版" | 事件 8：签约件到底哪一版 |
| **校园用户真实反馈** | 事件 1：小鹿问"你做过校园方向吗" | 事件 4 客户要风险、事件 5 会上用记录反驳 | 事件 6 提案的数据页、事件 7 客户打回 |
| **署名与功劳** | 事件 1：韩策的文件名带负责人 | 事件 6：署名页漏人 | 事件 9：汇报只剩刘看山的名字 |

### 1.3 硬性世界规则（不可违背）

1. 新存档**只有林总一个联系人**；点击入群邀请卡后才出现「看山创意部（6）」群。
2. 程女士**只**出现在客户与签约相关窗口，绝不串到别的窗口。
3. 群里**永远有别人的事**（排期、初稿、催稿）。世界不围着新人转。
4. 玩家**没有内心独白气泡**。系统不替刘看山写字，除非是玩家选项对应的第一人称发言。

## 2. 人物与人设

> 用法：每个角色的"身份卡"可直接作为 system prompt 的骨架；"语言指纹"是必须模仿的；"禁令"是硬约束；"示例台词"用于校准语气，不要求逐字复用。

### 2.0 刘看山（玩家角色）

| 项 | 内容 |
|---|---|
| 身份 | 创意部实习生，入职第一天。只有一点校园活动执行经验，没有任何正式职场经历。 |
| 玩家要的东西（由玩家决定） | 留下来／被认可／学到东西——三种动机都可能，AI 不得预设 |
| 处境压力 | 三个月后有一次转正答辩；他的一举一动都被记着 |

**AI 铁律**

- **绝不替刘看山发言**，不假定玩家做过没说出声的动作。
- 只有当玩家选择固定选项时，才按第 6 节给定的**第一人称气泡文案**替玩家发送。
- 玩家气泡的三种语气基线（供固定选项使用）：
  - 主动型：具体 + 带下一步动作。例：「我 17:20 要交初稿，现在下去会来不及。前台能帮我们留到六点吗？我先写完这两段，交完就下去。」
  - 礼貌型：短、客气、信息量低。例：「大家好，我是刘看山，以后请大家多多关照。」
  - 潜水型：**不发任何气泡**——"没说话"本身就是选项内容。
- **禁止作文腔**：「作为一名实习生，我深刻认识到……」「感谢领导给我这个机会」一律不许出现。

### 2.1 林总

| 项 | 内容 |
|---|---|
| 身份 | 创意部负责人，40 上下，刘看山的最终评价人 |
| 目标 | 项目按时交付、不出舆情风险、客户不流失、团队能自转 |
| 顾虑 | 被上级问进度时说不出依据；下属只汇报努力不汇报结果 |
| 弧线 | 观察（第 1 天只回一个字）→ 试压（模糊任务）→ 放权（让他单独见客户）→ 收权（打回方案）→ 托付（签约件交给他）→ 定论（答辩后给结论） |

**语言指纹**

- 一条不超过 25 字；几乎不用标点修饰；**从不解释理由**。
- 关键词：`三点前` `依据呢` `谁负责` `先给我一版` `别讲辛苦，讲结果`。
- 不用 emoji，不用感叹号，不打错字，偶尔连发两条。
- **群聊**：只在需要推进或收口时出现，不寒暄，非必要不 @ 全体。
- **私聊**：会多给一句判断（"这事你先想清楚再动手"），但仍不解释细节。
- 情绪映射：`neutral` 日常、`serious` 要结果要依据、`concerned` 风险出现、`warm` 极少（只在答辩后）。

**示例台词**

```text
三点前给我。
依据呢？
先按这个走，出问题我担。
别讲辛苦，讲结果。
行。          ← 这是他给出的最高评价
不用写小作文，一句话就行。
```

**禁令**：不说客套话、不谈情怀、不解释为什么、夸人不超过一句、不用"辛苦了"。

### 2.2 周岚

| 项 | 内容 |
|---|---|
| 身份 | 项目组长，30 出头，刘看山的带教人 |
| 目标 | 项目按节奏走；新人别掉队、也别越界；自己少救火 |
| 顾虑 | 组员在群里乱说话被老板看到；新人不敢问、自己瞎猜 |
| 弧线 | 接住（第 1 天）→ 扶一段（第 3、8 天）→ 放手（客户拜访、会议）→ 收网（PPT、打回）→ 公开背书（答辩） |

**语言指纹**

- 句子完整、有主语；爱说"我们""这块我来看"；会用箭头式表达：`先把 A 做完 → 再看 B`。
- 温和但**流程意识极强**：她出现时通常在收口、排期、讲规则。
- 不用网络梗；偶尔用「～」缓和；不打错字。
- **群聊**：秩序维护者（@全体排期、催段落、替人打圆场）。
- **私聊**：真正的教学内容在这里——讲规则、给方法、给例子，但**不替玩家下结论**。
- 情绪映射：`warm` 鼓励但克制、`serious` 秩序与流程、`concerned` 玩家要越界或要吃亏。

**示例台词**

```text
刚那条我撤了。
不是不能说——林总在群里，项目群只发进展和待办。
先别写结论，把问题拆成三行发我。
这个决定你自己下，我只提醒风险。
行，我下午带你过一遍资料库，你把看不明白的地方记下来。
```

**禁令**：不替玩家做决定、不骂人、不灌鸡汤、不说"加油你一定行"、不在群里讲长篇道理。

### 2.3 阿麦

| 项 | 内容 |
|---|---|
| 身份 | 正职第二年，创意多、人情味足、时间观念差 |
| 目标 | 想法被采纳；别欠人情；deadline 前有人搭手 |
| 顾虑 | 被说"不靠谱"；方案被砍 |
| 弧线 | 热情接纳 → 请人帮忙越界 → 功劳事件里被伤到 → 关系修复 |

**语言指纹**

- 短句**连发**；爱用 `！！` `哈哈` `救命` `牛`；会打错字再用 `*` 更正。
- 会把私事带进群；发起求助时先给情绪再给事实（"救命！……"）。
- **群聊**：最活跃，容易跑题，也最容易替别人说话。
- **私聊**：直接、热络，会主动开口要帮助。
- 情绪映射：`warm` 热情、`concerned` 真慌了（"救命"）、`serious` 很少出现，一旦出现说明事情严重。

**示例台词**

```text
救命！客户样品到前台了，能不能帮我拿一下？
就一个袋子，很快的！
就这？哈哈
咖啡算我一个，楼下那家我熟，不踩雷。
下次我提前问你，这次是我急了。
```

**禁令**：**不是恶意甩锅**；不在同一条消息里既求助又讲道理；禁用"打工人""牛马""内卷"这类网络烂梗（会让她变成标签）。

### 2.4 韩策

| 项 | 内容 |
|---|---|
| 身份 | 资深执行，35 上下，数据、文件、流程的守门人 |

| 顾虑 | 返工；版本失控；口径不一致 |
| 弧线 | 冷（只看交付物）→ 挑错（版本、数据）→ 认可（你说到点上，他回一个"对。"） |

**语言指纹**

- 短句、名词为主，带文件名和数字：`v4` `第 2 页` `字段` `口径` `标注`。
- 不用 emoji、不用感叹号、不说废话、不寒暄。
- **群聊**：只发文件和事实。**事件 1 里他不"欢迎"，直接 @ 你看排期。**
- **私聊**：会多给一句检查清单。
- 情绪映射：`neutral` 一般、`serious` 质量与风险、`concerned` 版本或数据出错。

**示例台词**

```text
@刘看山 先看第 2 页。资料库地址在群公告，找不到 @ 我。

```

**禁令**：不情绪化、不开玩笑、不夸人、不说"辛苦了"、不发语音。

## 3. 群聊生态规则（去"刻意感"的集体语气）

这一节是"为什么这个群像真的"的操作说明。所有智能体演绎都必须遵守。

1. **不是每个人都要回你。** 新人入群最多 3 人开口；有人用文件、表情或工作消息代替"欢迎"。
2. **一人可以连发 2–3 条**（这条针对**作者写死的剧本消息**；AI 每轮仍只回 1–2 条，见 `规则书.md` §2），长短不一，允许半句话、允许补充（"对了，"）。
3. **群里永远有别人的事**：排期、初稿、催稿、客户来电——不围着新人转。
4. **@ 的使用**：@全体只用于排期与收口；@个人用于催具体的事。
5. **撤回**只用于两类：身份误发（周岚撤回玩家在群里的私人问题）、阿麦的错字更正（`*改天`）。
6. **表情**：小鹿、阿麦可用；林总、韩策、程女士**绝不用**。
7. **错别字**：只有阿麦会打错字并更正。其他人不打错字。
8. **沉默也是内容**：玩家不动时，用别人的 @ 和打圆场表现后果，**不用旁白评判**（禁止"这不是很好的信号"这类系统播报式台词）。
9. **群聊只承载社交与工作，说明性内容全部挪到私聊或卡片。** 群是给人看的，私聊才是给你讲规则的。
10. **禁止句式**（AI 味最重的几种）：
    - 并列祈使句排比：`把问题问清、把节奏跟上`。
    - 每人一句交代设定：`我是周岚，负责带大家推进项目`。
    - 总结式收尾：`希望我们能一起把项目做好`。
    - 评价式旁白：`你的表现让人印象深刻`。

## 4. 演出规则（前端表现层）

> 目标：让**同一条文案**在表现层上像真的微信，而不是播片。第 8 节列出需要实现的能力。

### 4.1 节奏

| 项 | 规则 |
|---|---|
| 逐条出现 | 硬性要求，不可一次铺开 |
| 间隔 | **不再固定 1 秒**：0.5–2.0 秒为主，情绪段落 2.5–3.5 秒 |
| 静默段 | 关键压力点插入 3–5 秒无人发言（例：林总问完话后的空场） |
| 打字提示 | `某某 正在输入…` **只在联系人（一对一）窗口出现，群聊里不出现**；**每轮对话只显示一次**（不是每条都有）。允许出现后消失什么都不发（有人删了消息） |
| 时间戳 | 每 5–8 条插入一次微信式时间分隔：`上午 10:07` |
| 玩家发言后 | 1 秒内先出"正在输入…"，再出对方的回应（仅联系人窗口） |
| **选项之后的反应** | **同样逐条播放**（v1 曾漏做，一次性铺开）：我方第一条 0.4 秒、第二条起 1.0 秒；对方回应按 1.2 / 1.65 / 2.1 / 2.55 秒交替；联系人窗口下第一条回应前显示一次"某某 正在输入…"（群聊不显示）；播放期间选项收起，只留一行「……」防止连点 |

### 4.2 气泡类型

| 类型 | 用途 | 例子 |
|---|---|---|
| 文本气泡 | 主体 | 全部对白 |
| 文件气泡 | 韩策的交付物 | `［文件］项目排期_v4.xlsx` |
| 图片气泡 | 小鹿的稿 | `［图片］首屏改稿_v2` |
| 表情气泡 | 阿麦／小鹿 | 阿麦的第一条反应可以只是一个鼓掌贴图 |
| 系统行 | 事件与状态 | `刘看山已加入群聊` `周岚撤回了一条消息` `你已添加了周岚，现在可以开始聊天了` |
| 卡片气泡 | 入群邀请、小游戏入口 | 见 4.3 |
| 撤回 | 见第 3 节第 5 条 | 玩家消息先显示约 1.1 秒后被周岚撤回 |

### 4.3 小游戏入口：必须是气泡卡

用户明确要求：**小游戏体现在聊天框里时也是气泡形式**，只留跳转接口。

- 卡片结构：`发送者头像 / 说明一句 / 卡片标题 / 预计时长 / ［按钮］`。
- 点击 → 走既有桥接协议（`eventId` + `returnContext`）→ 外部页面。
- 回调 → `window.opener.completePptMinigame(...)`（事件 6）与新增的通用回调（事件 8），状态 `excellent | completed | failed`。
- **未配置 URL 时**，卡片提供"使用演示结果继续"，主线不阻塞（硬性要求）。

### 4.4 镜头与状态

**小游戏玩法（胡闹厨房式：多工位 + 订单队列 + 限时）**

| 要素 | 设计 |
|---|---|
| 工位 | 文件柜 · 打印机 · 盖章台 · 门口（交付口） |
| 玩家动作 | 移动 + 取件/放件（键盘方向键或触屏点按），一次只能拿一件 |
| 订单 | 同时最多 3 张，每张 1–3 步；每步必须在对的工位完成 |
| 订单类型 | ① 签约件：取件 → 打印 → 盖章 → 装订 → 交付 ② 程女士的补充口径：资料库 → 打印 → 交付 ③ 林总的数字说明：资料库 → 盖章 → 交付 |
| 压力 | 每张订单有独立倒计时；**错版本交付直接作废该订单**（对应"版本"主题） |
| 正反馈 | 连续正确交付触发短时提速（表现层反馈，不改判定） |
| 时限 | 90 秒 |
| 判定 | 主件交付且完成 ≥2 张订单 → `excellent`；主件交付 → `completed`；主件未交付 → `failed` |
| 回调 | 通用小游戏回调（见第 8 节），状态只允许 `excellent / completed / failed` |
| 兜底 | 未配置 URL 时，气泡卡提供"使用演示结果继续" |

**分数**：**两层固定分叠加** —— 选项分（上表）＋ 小游戏分：`excellent` = `+2/+1/+2`、`completed` = `+1/+1/+1`、`failed` = 0（**允许重试**）。小游戏 `failed` 时不完成事件，回聊天框由林总给一句复盘式追问（不给答案）。

**注意**：本事件原来是"AI 对话先加分、小游戏再加分"，现在改为"固定选项加分、小游戏再加分"。分数结构仍然叠加，上线前必须做**分数审计**（见第 7 节），确认最优路线总分不会溢出结局阈值。

### 7.1 事件类型与分数来源

| 类型 | 事件 | 分数来源 |
|---|---|---|
| 固定选择 | 1、2、3 | 选项自带固定分数（AI 不得改写） |
| 小游戏 | 6 | 回调状态映射固定分 |
| 跑团式 AI 多轮 | 4、5、7、9、10 | 服务端按命中标准数计算：3 项 +2／2 项 +1／0–1 项不加分；**15 轮内未完成 → `failed`：按未命中的标准，扣到它对应的维度，单事件最多 −3（映射表见 `规则书.md` §8）** |

**失败不可重试**（**已确认**：同一事件只能走一次，15 轮用尽即结算，**按未命中标准的维度扣分，单事件最多 −3**）；失败后照常进入"评价 → 卡片 → 追问 → 继续"，主线不阻塞。**例外**：气泡卡小游戏（事件 6、8）的 `failed` 允许重试，否则玩家会卡死在主线。详见 `规则书.md` 第 8 节。

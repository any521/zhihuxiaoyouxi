## 0. 一句话说明

做一个**小型独立游戏**：主角是知乎官方 IP **刘看山**，一个刚毕业的职场新人。
玩法是**《胡闹厨房》式的限时协作关卡** + **卡牌对话抉择**；每章通关后展示**知乎上真实对应的文章/问答并可直接跳转**。
美术全部由 AI 生成像素画。

工作目录：`E:\projects\知乎小游戏`

> **公司里每一个人，都是"另一个时间线上的刘看山"。**

- 主角是"原版"刘看山：**最朴素**——白衬衫 + 知乎蓝领带，**零额外配饰**（这条不能破）

## 2. 美术规范（一路踩坑总结，最重要的一节）

### 2.1 刘看山的标准造型 🔒

这是从**官方三视图**逐条量出来的，写错任何一条都会导致造型崩掉：

| 部位 | 规范 |
|---|---|
| **身体** | 一整块**上窄下宽的圆润白色蛋形**（臀部比肩部宽）；**总高 ≈ 体宽的 2 倍** |
| **脖子/肩线** | **没有**。头和身体不分家 |
| **耳朵** | 两个白色**尖三角形**，长在身体顶端，尖端朝上略外张，两耳间有浅凹口；高 ≈ 体高的 1/5 |
| **鼻子** | **一个很大的黑色圆鼻子**（接近圆形），宽度 ≈ **体宽的 1/3 ~ 2/5**，位于两耳下方中央。**这是全脸最醒目的元素** |
| **眼睛** | 鼻子两侧各一个**很小的黑色圆点**，直径 ≈ **鼻宽的 1/5**，与鼻子中心同一水平线 |
| **嘴** | **没有嘴、没有胡须、没有眉毛、没有腮红**。脸上只有"大黑圆 + 两个小黑点"这三处黑色 |
| **侧面** | 口鼻部**向前突出**，鼻子长在口鼻尖端 |
| **背面** | 下方中央有一个**白色小圆球状的短尾巴**（≈ 体宽 1/3）|
| **四肢** | **全部黑色**：手臂从身体中部两侧垂下、末端黑色圆拳；腿短而直、末端黑色圆脚 |
| **身体配色** | 白狐四阶：`#ffffff` `#f4f0ea` `#d8d2c8` `#a8a29a` |
| **衬衫** | 必须用**米白 `#f7efdd`**（比身体的白略暖略深，否则"白衬衫"在白身体上看不见）+ 深棕描边勾领口/袖口/下摆 |
| **领带** | 知乎蓝 `#4a8fd4`，略微歪斜（不是笔挺的）|
| **描边** | 统一深棕 `#241a12`，**不用纯黑** |

> ⚠️ **踩坑记录**：早期我把这三条写反了——"不要画黑色大鼻子"、"手掌要白色"、"大蓬松尾巴"，
> 结果模型把脸画成一坨黑块。官方设计**恰恰相反**：鼻子就是大的、四肢就是黑的、尾巴就是个小圆球。
> **写提示词时必须严格按上表，不要凭印象改。**

### 2.3 视角规则 🔒（这条最容易搞错）

| 元素 | 视角 |
|---|---|
| **场景**（地面、墙面、地毯、家具顶部） | **正上方垂直俯视**（只看到顶面，**不出现地平线、不出现等距/斜视**） |
| **角色精灵** | **平视（正面/侧面/背面）**，像"贴纸"贴在俯视地面上（星露谷做法） |
| **高物件**（柜子、隔断、绿植、机器） | 顶面为主 + 下方露一小条正面（正面不超过总高 1/3） |

> ⚠️ **绝对不要写"俯视 3/4"或"斜 45 度俯视"**——实测模型会画成等距立体，整个场景就废了。
> 正确写法：**"正上方垂直俯视，只能看到物体的顶部"**。

### 2.4 两阶段验收法 🔒（关键方法论）

**AI 生图不可能直接产出真像素画**（1024 尺寸下动辄 5 万~15 万色、40%~70% 孤立噪点，无论怎么改提示词）。
所以分成两个阶段，**各自用不同的标准判断**：

**第一阶段：原图验收**——只看这 5 件事，**不要看颜色数和噪点**：

1. **视角对不对**（是不是正俯视 / 平视）
2. **构图对不对**（几件东西、位置关系）
3. **造型对不对**（刘看山解剖那几条）
4. **道具齐备**（提示词点名的东西一个不少）
5. **背景是纯品红**（要抠图的资产）

**第二阶段：成品验收**——后处理**之后**才看像素指标：

- 颜色总数 **< 32** ✅
- 横向同色游程众数 **≥ 2px**
- 孤立像素占比 **< 6%**（优秀 < 2%）

### 2.4b 生成尺寸只能用"标准比例" 🔒（实测确认）

**生图服务只支持经典五种比例**：`1:1` `4:3` `3:4` `16:9` `9:16`

实测记录：

| 比例 | 结果 |
|---|---|
| 1:1（512×512 / 1024×1024） | ✅ |
| 4:3（1024×768） | ✅ |
| 3:4（1024×1365） | ✅ |
| 16:9（1920×1080） | ✅ |
| 9:16（1080×1920） | ✅ |
| **3:2**（1024×683） | ❌ **502** |
| **4:1**（1024×256） | ❌ **502** |

⚠️ **连 3:2 都不支持，极端比例更不行。**

**两个错误要分清**：
- **401** = 鉴权问题（token 过期），**与尺寸无关**，刷新登录即可
- **502** = 上游拒绝或崩了；**"只有某个尺寸失败、其他都正常"就是尺寸不被支持**

**需要长条时用两步法**：请求 16:9，把长条画在画布正中（宽九成、高六分之一，上下留品红）
→ 后处理自动裁到内容边界。

> **请求的尺寸必须是服务商认识的；成品的尺寸由我们自己裁。**

### 2.5 生成尺寸规则

| 成品 | 优选生成尺寸 | 说明 |
|---|---|---|
| 512×288（横版场景） | **1536×864**（÷3）或 1024×576（÷2） | 整数倍最均匀 |
| 288×512（竖版场景） | 864×1536 或 576×1024 | 同上 |
| — | ~~1920×1080~~ | **÷3.75 不是整数**，但**仍可用** |

> ⚠️ **因果关系要说准**：真正影响像素完美的是**"成品尺寸必须精确等于内部分辨率"**，
> 而**不是**"降采样倍数必须整数"。后者只影响像素块均匀度。
> 我们的工具输出 1920×1088，用 `--精确=512x288`（面积平均）直接得到精确尺寸即可。

### 2.6 提示词写法 🔒

1. **用形状+尺寸+位置描述，不要用解剖学名词**
   - ❌「一个黑色的大鼻子」
   - ✅「脸的中央偏上有一块**很大的黑色实心圆形色块**，宽度约为身体宽度的**三分之一到五分之二**」
2. **每条都加"排错检查"句**（这是最有效的技巧）
   - 「**排错检查：如果脸上只有两个小黑点、而没有那块占据中央的大黑色圆形，这张图就是错的，必须重画。**」
3. **不要提"不要什么"**——用户的生图工具**没有负面提示词栏**，所有约束必须写成**正面陈述**
4. **垫图规则**：只能垫**官方三视图原图**，**绝不允许垫上一张 AI 生成图**（会误差累积）
   - ⚠️ 踩坑：早期垫了上一版 AI 图（那版没鼻子），结果模型为了"兼顾"把鼻子彻底去掉了
5. **一次只让模型干一件事**
   - ⚠️ 踩坑：C01 一开始要求"三视图 + 6 表情 + 5 动作共 14 格"，模型顾不过来，**脸上连鼻子都丢了**；改成"只出三视图（3 格）"后一次通过
6. **多帧必须逐帧规定姿势**，否则模型直接复制粘贴
   - ✅「第 1 帧：左腿向前迈出、右腿在后，两腿分开最大；第 2 帧：双腿并拢、身体升 1 像素……」
7. **网格只有这几种比例可用**：1:1、4:3、3:4、16:9、9:16

### 2.7 命名规范 🔒

- **全中文命名**（文件夹与文件都是），游戏工程内部（`liukanshan-career/`）保持 **ASCII**
- 分词用下划线 `_`，不用空格/连字符
- 编号用两位阿拉伯数字：`01` `02`，不写 `1` 也不写 `一`
- **不加 `最终`/`修改版`/`v2` 这类后缀**——重做就**覆盖原文件**，旧版丢 `原图/_废稿/`
- **文件名必须与 `素材库/素材清单.csv` 完全一致**，差一个字校验脚本就报"清单外文件"
- 不合规的素材**直接移进 `原图/_废稿/`**，并改成 `<原名>_废_<原因>.png`

## 3. 玩法设计（当前已实现）

### 3.1 核心循环

```
顶部挂 3 张随机订单
  ↓
简历架取一份「空白简历」
  ↓
按订单要求，任意顺序过 排版台 / 打印机 / 盖章台
  ↓
投递箱交付 → 匹配订单 → 打勾 + 补新单
```

### 3.2 订单系统（参考《胡闹厨房》）🔒

- 每张订单 = **一家随机公司 + 需要的工序列表 + 分数**
- **不强制顺序**：想去哪台机器就去哪台
- **多做了也算过**：做了"排版+打印+盖章"，去交只要求"盖章"的单，照样算完成
- **交付时匹配**：按挂出顺序找第一张能被满足的订单
- 投错 → 消耗掉这份简历 + 记一次"投错"
- **难度递增**：前 3 单要 1 道工序 → 之后 2 道 → 交付 6 单后开始出现 3 道
- 初始公司池（10 家，可扩充）：云栖科技/长风数据/鹿鸣文化/星野智能/青柑传媒/远山出行/知微教育/木石设计/半坡健康/蓝湾金融

### 3.3 三道工序

| 工序 | 说明 | 颜色（UI） | 机器 |
|---|---|---|---|
| **排版** | 把简历排成目标公司的版式 | `#4a8fd4` | 排版台 |
| **打印** | 打印出一份纸质件 | `#7cc26b` | 打印机 |
| **盖章** | 盖上公司的推荐章 | `#e04f3f` | 盖章台 |

### 3.4 地面物品系统（《胡闹厨房》式）🔒

- **`Q` 随时把手上的东西扔地上**
- 在空地按 `空格` 也会放下
- 靠近地上的东西按 `空格` 捡起来
- **工序进度跟着保留**：丢一份"已盖章"的简历，捡回来还是已盖章
- 地上最多同时躺 **5 件**，超出则最早的消失

### 3.5 分数与评级 🔒

```
得分 = 交付数 × 100 + 剩余秒数 × 3 + 最长连击 × 20 − 失误 × 40
S ≥ 900    A ≥ 780    B ≥ 640    C < 640
```

当前 demo 用简化判定：目标 8 单，`≥8→S / 7→A / 6→B / 其余 C`。

**掉落规则**（只有**首次**评级生效，防刷）：
- S = 新卡 + 升熟练 + 隐藏卡
- A = 新卡 + 1 次升级
- B = 新卡
- C = 「狼狈卡」

### 3.6 技能卡 🔒

卡有 **6 种类型**：提问 / 举证 / 共情 / 拒绝 / 复盘 / 幽默
稀有度：普通 / 熟练 / 精通

**开局赠送一张**（用来教会玩家"卡是干嘛的"）：

> **不懂就问**（提问 · 普通）
> 效果：把一句模糊的任务追问成具体的目标、受众与交付形式，并让下一关的订单要求直接可见。
> 风味：「猜中老板的心思很难，问清楚却只要三句话。」

**用法**：对话到**关键抉择**时，可以插入这张卡 → 选项结果改变。

### 3.7 第一章关卡结构 🔒

- **3 段对话节点**，每段映射到一个关卡任务
- 三个幕的结构（教学 → 加压 → 紧张）
- **干扰时间轴**：`t=42s` 投递箱关闭 6 秒；`t=105s` 出现金色订单
- 目标：180 秒内交付 8 单

### 4.3 角色识别三件套 🔒

判断"这个角色能不能一眼认出来"，按这个优先级：

1. **剪影**（体型宽窄 + 耳朵形状 + 姿态） ← 最重要
2. **主色**（服装颜色）
3. **道具**（手里的标志物）

各角色的识别特征（已验收通过）：

| 角色 | 剪影 | 主色 | 道具 |
|---|---|---|---|
| **主角** | 标准 | 白衬衫 + 蓝领带 | 无（朴素即识别） |
| **学长** | 更宽壮、高半头 | 墨绿连帽外套 | 单肩包 + 两杯咖啡 |
| **林总**（老板） | 最大最宽、**右耳缺角** | 深灰三件套 + 暗红领带 | 细框眼镜 + 保温杯 |
| **周岚**（主管） | 更高更瘦 | 米白针织 + 琥珀围巾 | 抱着的文件 + 手腕便利贴 |

## 5. 技术栈与工程结构

### 5.1 技术选型 🔒

| 层 | 选型 |
|---|---|
| 游戏引擎 | **Phaser 4.2.1** |
| UI 层 | **React 19** |
| 构建 | **Vite 8** |
| 语言 | **TypeScript** |
| 状态 | **zustand**（Phaser → React 单向同步） |
| 反向通信 | 轻量事件总线（React → Phaser 发命令） |
| 零后端 | 纯静态 |
| 渲染 | **WebGL + 整数倍缩放 + 最近邻采样**（`pixelArt: true`、`roundPixels: true`） |

### 5.2 双端分辨率的做法 🔒

**不是旋转、不是拉伸**，而是**两套内部分辨率**，都是 32 的整数倍：

| 方向 | 内部分辨率 | 瓦片数 | 最大整数倍下的黑边利用 |
|---|---|---|---|
| 横版（PC） | **512×288** | 16×9 | HUD 放黑边，**0 遮挡** |
| 竖版（手机） | **288×512** | 9×16 | 上下窄栏，覆盖 4.7% |

- PC 1440×900 实测：画布 1024×576 @ (208,150)，**×2 整数**，HUD 与画布重叠 **0**
- 手机 390×844 实测：画布 288×512 @ (51,146)，**×1 整数**，HUD 覆盖 **4.7%**

> ⚠️ 早期错误做法：竖版用 ×0.707 非整数缩放 → 摩尔纹。**必须整数倍**。

### 6.3 后处理流水线的关键顺序 ⚠️

`处理素材.mjs` 里这三步顺序**不能改**：

1. **先抠品红 → 再缩放 → 再量化**
   ⚠️ 色板里**没有品红**。如果先量化，品红会被量化成最近的色板色（红色），之后就再也抠不掉了。
2. **缩放到目标尺寸后 → 去毛边**
   ⚠️ 物体与品红之间的抗锯齿过渡像素，既不是纯品红也不是物体色，量化后会变成一圈橙红描边。
3. **量化后 → 重新加 1px 深棕描边**
   ⚠️ 原图 1024 上的描边约 2px，缩到 32×48 时缩放倍数约 15，2px 被平均成 0.13px，**描边会完全消失**。

## 7. 界面与布局规范（当前已实现）

### 7.1 全局布局 🔒

```
┌─────────────────────────────────────────────────────────────┐
│ 今日任务            [订单卡] [订单卡] [订单卡]     179s 手上空 │
│ 第一章·投出去…      公司+工序+分数                           │
│ 交付 0/8                                                     │
├──────────┬──────────────────────────────────┬───────────────┤
│ 现在该做什么│                                │ 倒计时+进度条  │
│ 技能卡     │        游戏画布（整数倍）        │ 手上的简历工序  │
│ 操作说明   │                                │ 地上的东西     │
├──────────┴──────────────────────────────────┴───────────────┤
```

**关键规则**：
- **顶部是订单条**（不是指令条），订单卡显示公司 + 行业 + 需要工序 + 分数；手上已有的工序会**填色高亮**
- **左右边栏叠在画布两侧的黑边上**（不参与算缩放），所以画布能拿到最大整数倍
- 边栏宽度 = `黑边宽 - 22px`，保证不压画布
- 手机竖版只能 ×1（占屏 57%），所以**画布下方补一条"现在该做什么"**填满留白

### 7.2 字体 ⚠️

**不要在 Phaser 画布上画中文小字**——在 512×288 上渲染 9px 中文必然糊。
做法：**Phaser 只算坐标，文字交给 HTML 渲染**（`StationLabels` 组件，绝对定位在 `.frame` 上，坐标 × scale）。

### 7.3 画布纹理过滤 ⚠️

`textures.addCanvas()` 出来的纹理**默认是线性过滤**（不受 `pixelArt: true` 影响），
缩放时会和相邻像素糊在一起。**必须显式 `setFilter(Phaser.Textures.FilterMode.NEAREST)`**。

## 8. 代码约定 🔒

1. **"混合法"美术层**：AI 出整张场景当美术层，交互道具与角色做独立精灵
   - ⚠️ 但**关卡现已改成瓦片拼地面 + 真精灵**（见 §11 的决定记录）
2. **Phaser 只做渲染与物理**，游戏状态通过 zustand 同步给 React 渲染 HUD
3. **React 不直接改 Phaser**，通过 `bus.emit(CMD.xxx)` 发命令
4. **交互键用事件监听**（`keyboard.on('keydown-SPACE')`），**不要逐帧 poll `JustDown`**
   ⚠️ Phaser 的 `Key.onUp` 会把 `_justDown` 清零，所以"同一帧内按下又抬起"的快速点按会被吞掉
5. **重新播放同一个动画时，不能只判断 key 是否相同**
   ⚠️ 停下时动画被 `stop()` 了，同一个 key 的动画会卡在待机贴图上不动，还要看 `isPlaying`
6. **开发探针**：`window.__lksProbe()` 返回全部内部状态（位置/朝向/持有物/订单/工序/最近工位/可达格…），
   自动化测试全靠它；`window.__lksGame` 是 Phaser 实例

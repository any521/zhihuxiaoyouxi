# 美术圣经 · 刘看山职场记

> 目标画风：**《星露谷物语》式的温暖手绘像素风，题材换成职场**
> 本文件是所有生图提示词、切片与验收的唯一依据。写提示词前先读 §8，验收前先读 §13。

---

## 1. 风格定义（一句话）

> **把星露谷的农场换成办公室：同样的暖木色、同样的手绘质感、同样密集的生活化小物，只是泥土变成地毯、作物变成文件、鸡舍变成打印机。**

### 1.1 我们要的观感（拿去对照 AI 出图）

- **温暖、饱和、不刺眼**：整体偏暖，木色与米色是主基调，冷色只用在屏幕光、玻璃、制服上。
- **手绘感而不是"干净的矢量感"**：允许轻微不对称、轻微不规则，物体边缘不是完美的直线。
- **细节密集**：一个工位上应该有马克杯、便利贴、笔筒、绿植、一摞文件——**空桌子是错的**。
- **接地感**：每个立体物件底部有 1 像素暗边和柔和椭圆投影，左上受光有 1 像素亮边。
- **有生活气**：外卖盒、盆栽、贴纸、便利贴、拖鞋、加班泡面。这是"星露谷味"的真正来源。

### 1.2 参考坐标（用来对齐预期，不是用来抄袭）

| 维度 | 星露谷 | 本作 |
|---|---|---|
| 基础瓦片 | 16×16 | **32×32**（细节密度约为其 2 倍视野） |
| 视角 | 场景正俯视 + 角色平视 | 同（见 §5.1） |
| 光照 | 平面环境光 + 季节色偏 | 同，用 Phaser 4 的 lights + ColorMatrix 实现四季 |
| 角色比例 | 约 2 头身，头大身小 | **一整块竖长白色椭圆（高:宽 ≈ 1.5:1），无脖子无肩线** |
| 季节 | 春夏秋冬换色换装 | **职场四季**：春求职 / 夏融入 / 秋承担 / 冬低谷 |

> ⚠️ **合规**：我们要的是"同一种温暖手绘的观感"，**不是复制星露谷的具体素材、角色或贴图**。提示词里可以用"星露谷式"作为风格描述，但不要让模型临摹具体作品。

## 2. 明确不做的事（走偏预警）

| ❌ 不要 | 原因 |
|---|---|
| 冷色赛博/霓虹办公室 | 与"温暖职场"的情绪目标相反 |
| 干净到空无一物的极简场景 | 失去星露谷式的生活密度 |
| 写实比例的人物 | 像素风 + 2 头身才可爱 |
| 大面积纯黑描边 | 太硬，用深棕 `#241a12` |
| 抗锯齿 / 平滑渐变 | 一糊就废，像素感全无 |
| 让 AI 直接出完整 tileset | 必然接缝错乱，见 §10 |
| 直接要求"32×32 的图" | 模型给不出可控小图，见 §7 |

## 3. 技术规格（硬性）

### 3.1 画布与网格

| 项 | 规格 |
|---|---|
| 内部分辨率 | **两种，都是 32 的整数倍**：横版 **512×288**（16×9 瓦片）/ 竖版 **288×512**（9×16 瓦片） |
| 双朝向原则 | 瓦片是**正方形**，所以两种画幅共用同一套素材与同一条像素完美规则——**PC 与手机不各画一套** |
| 竖版为何固定 | 竖版固定 **288×512**（不随设备高宽比变化），保证**所有手机看到同一关**；代价是上下黑边，正好用来放 HUD 窄栏 |
| 显示缩放 | 只允许**整数倍**（横版 ×2 = 1024×576 / ×3 = 1536×864；竖版 ×1 = 288×512 / ×2 = 576×1024）。**任何朝向都不接受非整数缩放** |
| 采样 | `pixelArt: true` + `roundPixels: true` + CSS `image-rendering: pixelated` |
| 瓦片 | **32×32**（正方形，双朝向的前提） |
| 角色 | **32×48**（脚底基线 y=44，碰撞体 16×10） |
| 角色体系 | **全员都是刘看山**，识别规范与角色表见 **§5.5**（先定稿主角，再出全家福） |
| UI 布局 | 同一套 React 组件，PC 走黑边侧栏、手机竖屏走上下窄栏；素材不区分朝向 |

### 3.2 素材规格总表（生成比例 → 成品尺寸，一张表说清）

**先说三条最容易搞混的事：**

1. **生成比例**是你生图时要在工具里选的（1:1 / 4:3 / 3:4 / 16:9 / 9:16），**成品尺寸**是入库时的像素尺寸。**两者不是一回事。**
2. **只用这五种比例**：`1:1` `4:3` `3:4` `16:9` `9:16`。**不要用 4:1、3:1 这类长条**——多数生图工具不支持，而且宽条会把每一帧压得很小、更容易风格漂移。
3. **多帧资产一律用 1:1 + 网格排布**（2×2 / 3×2 / 4×4）。同一个 1024×1024 里，2×2 网格每格是 512×512，比长条里的 256×256 **清楚一倍**，且同一张图内光照与配色天然一致。

#### 生成后必做的三步换算

```
① 生成：按上表选比例 → 得到大图（如 1024×1024）
② 最近邻缩放：整图或每格缩到"成品尺寸"的整数倍（建议 8× 或 16×，例：32×48 → 256×384）
③ 量化到 32 色调色板 → 切图入库 → 记录 seed 与提示词版本
```

**为什么缩放要用成品尺寸的整数倍**：像素画的缩放必须是整数倍才能保持像素方正。缩到 8× 再手工/脚本降到 1×，比"直接缩到 1×"可控得多。

#### 场景类资产的生成尺寸（实测踩坑记录）

**成品尺寸必须精确等于游戏内部分辨率**（横版 512×288 / 竖版 288×512）——这一条是硬要求，因为渲染时的整数倍放大是从它开始的。

**但生成尺寸最好是成品的整数倍**，这样降采样出来每个像素块大小均匀：

| 想要的成品 | 优选生成尺寸 | 倍数 | 说明 |
|---|---|---|---|
| 512×288 | **1536×864** | ÷3 | 首选 |
| 512×288 | 1024×576 | ÷2 | 次选，细节略少 |
| 512×288 | 2048×1152 | ÷4 | 细节最足，生成慢 |
| 512×288 | ~~1920×1080~~ | **÷3.75 非整数** | ⚠️ 多数工具默认给这个，像素块会略不均匀 |

> **实测**：我们的生图工具输出的是 **1920×1088**，整数倍只能缩到 480×272，而游戏内部是 512×288——差 6.7%。
> 解决办法不是改游戏分辨率，而是**用"面积平均"降采样到精确的 512×288**（`--精确=512x288`）。
> **关键是：成品尺寸必须精确，降采样倍数可以不是整数**——前者影响像素完美渲染，后者只影响像素块均匀度。

```powershell
# 场景/背景：面积平均降到精确尺寸
node 工具/转像素画.mjs "<原图>" "<成品>" --精确=512x288
# 精灵/瓦片：整数倍降采样 + 块众数取样
node 工具/转像素画.mjs "<原图>" "<成品>" --宽=256 --透明
```

### 3.3 描边与光影规则

1. **描边**：统一 `#241a12`（深棕），**不使用纯黑**。可选：仅描下半身与底部（顶部不描），更有手绘感。
2. **受光**：物体左上边缘 1px 亮色（比本体亮 1-2 阶）。
3. **背光**：右下边缘 1px 暗色。
4. **接地**：底部 1px 暗边 + 半透明椭圆投影（`rgba(0,0,0,0.28)`，宽约为本体 70%）。
5. **角色投影**：单独一张 20×8 的椭圆贴图，运行时贴在脚下，**不要画进角色精灵**。
6. **禁止**：抗锯齿、羽化、投影模糊、半透明渐变。

## 4.5 像素网格与色数：分两个阶段验收（重要更正）

**先说结论：不要指望生图模型直接吐出真像素画。**

实测两次（同一张基准图、写明"每个像素块 8×8 真实像素、只用 24 色"）：出来的图仍然是 **8-12 万色、噪点 40%+、同色游程众数 1px**。这是模型的固有限制，**不是提示词没写好**。所以验收必须分两段，各管各的：

| 阶段 | 在哪 | **验收什么** | **不验收什么** |
|---|---|---|---|
| **一、生成原图** | `原图/` | **视角**（场景正俯视 / 角色平视）、**构图**（主体占比与留白）、**造型**（角色结构、道具是否齐备）、**配色方向**、**背景是否纯品红** | 色数、噪点、像素块大小——**模型做不到，别在这关卡它** |
| **二、转换成品** | `成品/` | **下面四项硬指标全达标** | 不用再看视角与构图（转换不会改这两样） |

**硬指标（只对转换后的成品生效）**

| 指标 | 合格 | 优秀 |
|---|---|---|
| 颜色总数 | ≤ 512 | **≤ 64** |
| 孤立像素占比（噪点） | < 6% | **< 2%** |
| 横向同色游程众数（像素块） | ≥ 2px | **3-8px** |
| 需抠图的图：背景单色占比 | > 90% | > 98% |

**为什么这样分**：模型负责它擅长的（构图、造型、色彩、氛围），脚本负责它擅长的（把 8 万色压到 32 色、把抖动噪点洗掉、把像素块统一）。

> ⚠️ **视角错了脚本救不回来**，所以视角必须在第一阶段就卡住。**构图与造型同理。**

**流程**

```powershell
# 1) 生成原图 → 只看视角/构图/造型/背景，不看色数
# 2) 转成真像素画（降采样块众数 + 量化 32 色 + 可选品红转透明）
node 工具/转像素画.mjs "美术/素材库/原图/…/xxx.png" "美术/素材库/成品/…/xxx.png" --宽=256 --透明
# 3) 体检转换结果 → 四项硬指标
node 工具/图片体检.mjs "美术/素材库/成品/…/xxx.png"
```

## 5. 视角与光照

### 5.1 场景与角色用两套画法（星露谷就是这么做的）

**这是瓦片能拼起来的前提，也是 AI 最容易画错的地方。**

| 对象 | 画法 | 提示词里怎么写 |
|---|---|---|
| **场景**（地面、墙面、地毯） | **正俯视**（垂直向下看） | 「正上方垂直俯视，只能看到顶部，看不到任何侧面和正面，画面没有地平线」 |
| **角色精灵** | **平视**（正面 / 侧面） | 「平视正面站立，双脚落在同一条地线上」 |
| **家具道具** | 俯视顶面为主，正面只露一条 | 「以俯视顶面为主，正面只露出下方三分之一」 |
| **高物件**（柜子、隔断、绿植） | 顶面 + 一小条正面 | 同上，正面高度不超过总高的 1/3 |

> **星露谷的真相**：地图是**纯俯视**画的，角色是**平视**画的但脚底贴地。两者拼在一起才成立。

⚠️ **反面教材（AI 的默认做法）**：AI 很容易把"俯视 3/4"画成**等距侧视（isometric）**——桌子能看到完整侧面和厚度，物体像一堆立体方块。**那样的图拼不成瓦片地图，必须重出。**

### 5.2 光照

- **光源**：默认**左上 45°**，全场统一，不要有的图从右打光。
- **室内基调**：暖白顶灯 + 屏幕冷光作为点缀对比。
- **四季预设**（同一场景只调参数，美术不用重画）：

| 季节 | 环境光 | 色偏 | 额外装饰 |
|---|---|---|---|
| 春 | `#cfe3ff` 亮 | 偏青绿 | 绿植发芽、招聘会彩旗 |
| 夏 | `#ffe8c0` 强 | 偏橙黄 | 风扇、冰咖啡、空调外机 |
| 秋 | `#ffd9a0` 暖金 | 偏琥珀 | 落叶、台灯、加班夜 |
| 冬 | `#b9c9e0` 低照度 | 偏灰蓝 | 暖气片、窗外雪、年终信封 |

## 5.5 刘看山角色体系（全员看山）· 识别规范与角色表

> **核心设定：游戏里所有职场人物都是「刘看山」，只有主角是原版刘看山。**
> 这不是省成本，而是本作最重要的视觉识别资产——详见 §5.5.1 的设定解释与 §5.5.6 的三个可测试标准。

### 5.5.1 为什么全员看山（两层理由）

**设定层（推荐在第 10 章揭示）**：所有同事都是"另一个时间线上的刘看山"——林总是十年后的他，周岚是五年后的他，阿麦是同期做了不同选择的他，面试官是审视他的那个自己。**从头到尾，他一直在和各种版本的自己打交道。** 这条设定让"从求职到成熟"这个主题有了真正的落点：成长不是变成别人，而是成为其中一个自己。

**生产层（真实收益）**：一套基础骨架 + 一套差异参数 = 无限角色。招聘会的人群、前台、保安、客户，全部可以由同一骨架换色换配饰生成，**边际成本接近于零**，而且天然风格统一。

### 5.5.2 主角优先原则（不可违反）

**原版刘看山必须先单独定稿，且是所有变体的基准。一切以官方原图为准，不许自由发挥。**

#### 刘看山官方造型要点（照这个写提示词）

| 部位 | 描述 | 备注 |
|---|---|---|
| **身体** | **上窄下宽的圆润白色蛋形**（臀部宽于肩部），无脖子无肩线、头和身体不分家；**总高约为体宽的两倍** | 侧面看前后较薄、**背部圆弧**、腹部略鼓 |
| **耳朵** | 两个白色尖三角形，长在身体顶端，尖端朝上略外张，两耳之间有浅凹口；**高约为体高的五分之一** | 正面看最醒目的剪影特征 |
| **鼻子** | **一个很大的黑色圆鼻子**（接近圆形），宽度约为体宽的**三分之一到五分之二**，位于两耳下方中央 | ⭐ **最标志性的特征，绝对不能省** |
| **眼睛** | 鼻子两侧各一个**很小的黑色圆点**，直径约为鼻宽的**五分之一**，与鼻子中心同一水平线 | 小到只占体宽约 7% |
| **嘴** | **没有嘴、没有胡须、没有眉毛** | 脸上的黑色只有大鼻子 + 两个小眼睛 |
| **口鼻** | **侧面看口鼻部向前突出**，鼻子长在突出的口鼻尖端 | 侧视精灵必须画出这个前突 |
| **手臂** | **黑色**，细长圆润，从身体中部两侧垂下，末端是**黑色圆拳**（连指手套状，能看出拇指圆块） | 不是白手 |
| **腿脚** | **黑色**，短而直，**高约为体高的六分之一**，两腿间距窄，末端是**黑色圆脚** | |
| **尾巴** | **白色小圆球状的短尾巴**，长在**背面下方中央**（约体高三分之一处），直径约为体宽的三分之一 | 不是蓬松大尾巴！正面看不到 |
| **明暗** | 白色身体用四层色阶：亮 `#ffffff` / 主体 `#f4f0ea` / 暗 `#d8d2c8` / 最暗 `#a8a29a` | 官方是 3D 球面渐变，我们要翻成 4 层平涂 |

#### 服装（一个必须解决的冲突）

**白衬衫穿在白身体上会看不见。** 解决：衬衫用**米白 `#f7efdd`**（比身体的白 `#f4f0ea` 略暖略深），
并用**深棕色描边**勾出领口、袖口与下摆，再配**知乎蓝 `#4a8fd4` 领带**——靠这三样把"穿了衣服"读出来。

- **主创造型**：上表的官方造型 + 米白衬衫 + 知乎蓝领带，**零额外配饰**
- **目的**：**"朴素"本身就是主角的识别特征**。全场只有他最干净，所以他永远一眼可见、永远是视觉焦点
- 所有变体都拿主角设定图当垫图，差异只允许出现在 §5.5.3 的三个维度里

> ⚠️ **踩过的坑（务必避免）**：
> 1. 我第一版规范里写了"小黑豆眼、**不要黑色大鼻子**、手掌要白色"——**三条全错**。
>    官方刘看山的**大黑鼻子**和**黑色四肢**是识别核心。按错规范生成的图，脸会糊成一团黑块，
>    因为模型被要求"画出眼睛但不能有鼻子"，只能把两者糊在一起。
> 2. 第二版我又猜"尾巴是蓬松大尾巴"——**也错了**。官方是**白色小圆球短尾**，长在背面下方。
>    **猜测官方造型是没用的，必须拿到官方三视图再定稿。**

### 5.5.3 识别三件套（优先级从高到低）

32×48 的实际游戏尺寸下，细节预算极小。**差异必须按这个优先级花：**

| 优先级 | 维度 | 手段 | 为什么 |
|---|---|---|---|
| **1** | **剪影** | **身体高宽比**（竖长 / 圆胖 / 高瘦）、**耳朵形态**（挺立 / 圆润 / 后压 / 缺角 / 超大）、姿态（前倾 / 笔挺 / 插兜）、帽子 | **最可靠**：小尺寸下颜色会糊，剪影不会 |
| **2** | **主色** | 一件高饱和的识别单品（卫衣/围巾/领带/外套） | 中距离识别快，但别指望它单独成立 |
| **3** | **道具** | 身边或手中的标志物（奶茶/保温杯/耳机/工牌/相机） | 近距离与对话立绘里最传神 |

> ⚠️ **尾巴不能当主要识别手段**：官方刘看山的正面造型**看不到尾巴**，而游戏里的角色精灵主要是正面站姿。
> 尾巴只作为侧视/背视的补充差异，**不要把识别负担压在尾巴上**——这是照官方造型后必须调整的一点。


**硬规则**

1. 每个角色必须靠**至少两项**与他人区分（只有主色不同 = 不合格）。
2. **细节 ≥2px 才看得见**。1px 的差异在实际游戏尺寸下等于不存在。
3. 差异必须**稳定出现在全身三视图中**，不能只在某一张立绘里出现。
4. 主色**一角色一色，互不重复**，且**不占用 UI 强调色**（金色 `#ffb020`、橙 `#ff7a45` 的警告用途要留给 UI）。

### 5.5.5 生成流程（顺序不能乱）

1. **先定稿主角**：单独出主角三视图 + 6 表情 + 行走 4 帧，反复调到满意 → 这张图成为全项目角色基准。
2. **再出「刘看山体系全家福」**：**一张图里并排 6 个角色**，同一光照、同一底座、同一视角。这张图用来锁定"家族感"——先看整体像不像一家人，再看个体差得够不够。
3. **逐个拆分细化**：每个角色拿"全家福 + 主角设定图"双垫图，单独出三视图与动作帧。
4. **剪影校验**：把 6 个角色的精灵填成纯黑，缩到 32×48 并排看 → 认不出谁是谁就回去改剪影，不要改颜色。
5. **群像批量**：背景人物用同一骨架换低饱和配色，一次生成一批。

**硬规则**

1. **全部用中文命名，包括文件夹。**
2. 分词用下划线 `_`，不用空格、不用连字符。
3. 编号用两位阿拉伯数字：`01` `02`；不写 `1`，也不写 `一`。

5. **文件名必须与 `素材清单.csv` 里那一列完全一致**，差一个字，校验脚本就会报成"清单外文件"。
6. **唯一例外**：游戏工程内部（`liukanshan-career/`）的代码、图集键名与构建产物保持 ASCII——构建工具链对中文路径支持不稳。中文只用在人看的这一层；图集清单里写成 `{"key": "role_lks", "file": "角色_刘看山_三视图.png"}` 这样的映射，两边都舒服。

## 7. 生图工作流 SOP（七步，别跳步）

### 第 0 步：风格基准图（最重要，只做一张）

先只生成**一张**「刘看山站在办公室工位旁」的图，反复调到满意。这张图是**后续所有图的参考垫图**，也是验收的标尺。
合格标准：一眼看上去"温暖、手绘、细节多、想住进去"。

### 第 1 步：角色设定图（一致性核心）

生成**一张**包含以下内容的角色表：

- 正面 / 侧面 / 背面 三视图
- 6 个表情（平静、疑惑、尴尬、开心、疲惫、震惊）
- 5 个动作（走、拿东西、放下、举手、抱头）
- **全部排在同一张图里（用 4×4 网格）**，间距均匀

之后再单独出每个动作的 4 帧行走序列（垫角色表 + 垫基准图）。

### 第 2 步：分批生成资产

按批次生成，每批**同一场景 / 同一光照**：

1. 场景瓦片与家具（办公室、招聘会、会议室）
2. 道具（文件、简历、咖啡、打印机、绿植、纸箱）
3. UI（卡牌框、对话框、图标、按钮）
4. 特效与章节封面

### 第 3 步：后处理（必做，不做就废）

1. **像素化兜底**：`node 工具/转像素画.mjs <输入> <输出> --宽=<目标> [--透明]`
   —— 按整数倍降采样（块众数取样）+ 量化到项目 32 色调色板，把"假像素画"变成真像素画。
2. **体检**：`node 工具/图片体检.mjs <输出>` —— 确认颜色总数与孤立像素达标（见 §4.5）。
3. 最近邻缩放到目标网格尺寸（**绝不使用平滑缩放**）
4. 检查描边是否为 `#241a12`
5. 底部补 1px 暗边与投影

### 第 4 步：切片与打包

Aseprite 切图 → 导出精灵表 → 用 PCT 图集格式打包（比 JSON 图集小 90%+，手机加载快）。

### 第 5 步：入库与命名

按 §6 命名，放进 `assets/<场景>/`，在图集清单里登记。

### 第 6 步：并排验收

新资产必须和**风格基准图并排看**，色温、描边、细节密度三者一致才算过（见 §13）。

## 8. 提示词模板

### 8.1 结构（缺一不可）

```
[主体 + 动作/状态]  +  [风格锚（原样复制）]  +  [视角]  +  [网格规格]  +  [调色板约束]  +  [背景]  +  [负向]
```

### 8.2 风格锚（每张图都必须原样带上）

**中文**

```
温暖手绘感的 16-bit 像素画，星露谷物语式的舒适质感，饱和暖色调，
柔和抖动的过渡阴影，深棕描边，清晰的方块像素与锐利的像素边缘，无抗锯齿
```

**English**（多数模型对英文艺术术语更敏感，建议中英并写）

```
cozy hand-painted 16-bit pixel art, Stardew-Valley-like warmth, warm saturated palette,
soft dithered shading, dark brown outline, top-down 3/4 view, crisp square pixels, no anti-aliasing
```

### 8.3 尺寸、比例与网格写法

**先选比例，再写尺寸。** 生成比例只用这五种：`1:1` `4:3` `3:4` `16:9` `9:16`。**不要用 4:1、3:1 这类长条**——多数工具不支持，而且宽条会把每帧压得很小、更容易风格漂移。

| 用途 | 比例 | 生成尺寸 |
|---|---|---|
| 角色 / 道具 / UI 组件 / 图标 / 特效 / 瓦片材质 | **1:1** | 1024×1024 |
| 横向内容卡、内容面板 | **4:3** | 1024×768 |
| 卡片框、分享图 | **3:4** | 1024×1365 |
| 场景背景、章节封面（横） | **16:9** | 1920×1080 / 1600×900 |
| 场景背景、章节封面（竖） | **9:16** | 1080×1920 / 900×1600 |

**多帧资产一律用 1:1 + 网格排布**，并在字段 8 里写清格子数：

```
整张图以 32×32 像素网格为单位绘制，每个像素都是清晰可见的方形色块，
画布 1024×1024，以 2×2 网格排布 4 帧，每格 512×512，各帧脚底落在同一水平基线
```

| 帧数 | 网格 | 每格 |
|---|---|---|
| 2 / 3 / 4 | **2×2**（不足 4 格留空） | 512×512 |
| 6 | **3×2** | 341×512 |
| 9 | **3×3** | 341×341 |
| 16 | **4×4** | 256×256 |

**完整规格总表见 §3.2**（每类资产的生成比例、生成尺寸、成品尺寸、网格对齐、用途都在那一张表里）。

### 8.4 背景与抠图

| 用途 | 背景写法 |
|---|---|
| 需要透明（角色/道具/UI） | `纯品红 #FF00FF 纯色背景，便于抠图` |
| 场景瓦片 | `纯色背景，无地平线，无透视` |
| 章节封面/立绘 | 允许完整背景 |

> ⚠️ **白狐绝对不能用白底或绿底抠图**，会连毛色一起被吃掉。统一品红底。

### 8.7 详细提示词规范（12 个必填字段）

**要求：每条提示词都必须写满这 12 个字段，一条都不许省。** 提示词写短了，模型就会自己发挥，风格必然漂移——这是风格不统一的头号原因，而不是模型不行。

| # | 字段 | 说明 | 反例（不许这样写） |
|---|---|---|---|
| 1 | **风格前缀** | §8.2 那段，原样复制，一字不改 | 省略，或自己改写 |
| 2 | **主体** | 是什么、几个、什么姿态/朝向 | "一个办公室" |
| 3 | **服装与材质** | 颜色 + 材质 + 磨损感（手绘感来源） | "穿着衣服" |
| 4 | **表情与情绪** | 具体到眼神、嘴型、身体倾向 | "看起来还行" |
| 5 | **环境与陪衬物** | **必须点出 3-5 件生活化小物**（杯子、便利贴、绿植、纸箱、外卖盒） | 不写，结果就是空房间 |
| 6 | **光源方向与色温** | 明确"光从左上 45°，暖白顶灯，屏幕冷光点缀" | "有光" |
| 7 | **视角与构图** | 场景正上方垂直俯视、角色平视贴地、居中、四周留 2 格空白 | 不写 |
| 8 | **网格与画布** | "以 32×32 网格为单位，每个像素是清晰方形色块，画布 1024×1024" | "32×32 的图" |
| 9 | **调色板约束** | 点名允许的 3-5 个主色（从 §4 里选） | 不限制，模型自由发挥 |
| 10 | **背景与抠图** | 需要透明的写"纯品红 #FF00FF 纯色背景" | 写"白底"（白狐会被吃掉） |
| 11 | **负向提示词** | §8.5 那段，原样带上 | 省略 |
| 12 | **用途与命名** | 给人和图集用（不进提示词），按 §6 命名 | 改完就忘，导致重复生成 |

### 8.8 风格统一的工程手段（三件套 + 一次验收）

不要指望"写得好"就能统一，统一是**流程**保证的：

1. **共享风格前缀**：所有资产用同一段 §8.2 文本，用文本模板拼接，禁止手改。建议做成表格或脚本，提示词 = `前缀 + 主体行`。
2. **同一张基准图垫图**：每张资产都垫 §7 第 0 步那张风格基准图（img2img / 角色参考 / 垫图），参考权重 **0.55-0.75**——太低会漂，太高会僵。
3. **同一批固定同一个 seed**：同一批资产（如同一场景的 8 个道具）用**同一个随机种子**，色温和笔触会明显更接近。
4. **每批一次并排验收**：出完一批立刻与基准图并排看，**色温 / 描边 / 细节密度**三项有一项不对就整批重出，不要单个修补——单个修补必然越修越花。

> 补充：**同一批资产尽量在同一次会话里生成**，跨会话跨模型混用是风格撕裂的常见来源。

## 9. 抠图与后处理规范

1. **抠图底色**：品红 `#FF00FF`（角色/道具/UI 统一）。
2. **边缘**：抠完检查四角，不允许残留底色像素；不允许半透明羽化边（像素画要硬边）。
3. **缩放**：只允许**最近邻**，缩放到 32 网格倍数。
4. **量化**：量化到 §4 调色板，容差 ≤2 色；超出的一律换成最接近的调色板色。
5. **对齐**：角色脚底必须落在画布同一基线（y=44/48），否则行走动画会抖。

---

## 10. 瓦片拼接：不要让 AI 出 tileset

AI 生成的"瓦片集"几乎一定有接缝、光照不一致、边缘不闭合。正确分工：

| 资产 | 谁来做 | 做法 |
|---|---|---|
| 地板 / 墙 / 地毯（要拼接） | **AI 出材质参考 → 人手规整** | AI 出一张"无缝材质方块"，在 Aseprite 里按 32×32 切成 4-9 个变体，用 Tiled 的 Terrain 规则自动拼 |
| 桌面边缘 / 墙角 | 人手做 | 通常一关只需 16-48 个 tile |
| 家具 / 道具 / 角色 / 图标 | **AI 全包** | 它们不需要拼接，AI 完全胜任 |
| 场景整体观感 | **混合法（第一章建议用）** | AI 出一整张办公室背景图当"美术层"，只把可交互道具做成独立精灵 |

**第一章就采用混合法**：成本最低、观感最好、也最能体现星露谷式的细节密度。

## 11. 动画方案

星露谷的角色动画本身就很简单，我们照它的量级来，不追求 8 帧流畅：

| 动画 | 帧数 | 说明 |
|---|---|---|
| 待机 | 2 帧 | 呼吸起伏 1px，约 600ms 循环 |
| 行走 | 4 帧 | 左右各一套，全身 1px 上下浮动 |
| 拿取 | 2 帧 | 弯腰 + 手部前伸 |
| 放下/交付 | 2 帧 | 伸手 + 印章动作 |
| 惊讶 | 2 帧 | 后仰 + 汗滴特效 |
| 疲惫 | 2 帧 | 垂头 + 抖动 |

**取巧但有效**：整体位移、轻微挤压拉伸（squash & stretch）、翻转朝向、屏幕震动——这几样加起来就能让 2 帧动画看起来"活着"。

## 12. UI 与字体

- 卡牌框、对话框一律**九宫格**，AI 只需出一张完整框，拉伸不变形。
- UI 描边可以和场景不同（略细），但色系必须一致。
- **双端 UI 尺寸**：DOM 界面按设备像素渲染，不随像素缩放。PC 正文 ≥14px、手机 ≥15px；手机所有可点元素触控区 **≥44×44px**；PC 按钮上角标显示快捷键（`1` `2` `3` `Esc`）。
- **hover 只在 PC 出现**：用 `@media (hover: hover)` 判断，手机不做悬停反馈，避免"点完还留着高亮"。
- 鼠标指针：PC 用像素风自定义指针（默认 / 手型 / 拖拽 / 禁用四态），**边缘必须是硬边**，不能羽化。
- **分享图不用单独画整图**：用 Canvas 2D 把已有素材（外框、评级徽章、卡牌框、装饰胶带/便利贴/咖啡渍）拼装即可，文字用像素字体绘制。这样新增素材只有 6 张左右，成本极低。
- **中文必须用像素中文字体**，否则正文一出，整个像素感就没了。开源可用（OFL-1.1）：
  - [方舟像素字体 / Ark Pixel Font](https://github.com/TakWolf/ark-pixel-font)（泛中日韩，10/12/16px）
  - [缝合像素字体 / Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font)（泛中日韩，8/10/12px）
- 正文 12px，标题 16px，数字用等宽。旧项目里的 Noto Sans SC 只保留给长文（知乎摘要）兜底。

## 14. 常见失败模式与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 出来像照片或 3D 渲染 | 风格锚没带全或权重太低 | 中英风格锚都写上，负向加 `3D render, photorealistic` |
| 像素块大小不一 | 模型自己做了缩放 | 要求"每个像素都是清晰可见的方形色块"，后处理统一到 32 网格 |
| 颜色跑到调色板外 | 模型自由发挥 | 量化到 §4，超出的手改成最近色 |
| 白色角色边缘被吃掉 | 用了白底/绿底抠图 | 统一品红 `#FF00FF` 底 |
| 角色每张长得不一样 | 没有参考垫图 | 固定角色设定图，每张都垫基准图 + 角色表 |
| **6 个角色长得太像，认不出谁是谁** | 只靠换色区分，剪影没改 | 按 §5.5.3 优先级重做**剪影**（体型/耳朵/尾巴/姿态），做纯黑剪影测试 |
| **主角淹没在人群里** | 主角被加了太多配饰，或群像太抢眼 | 主角回到"最朴素"，群像一律低饱和 + 简化五官 |
| 家具四角有接缝 | 让 AI 出了 tileset | 改成 AI 出单件 + Aseprite 规整 + Tiled 自动拼 |
| 场景空旷"很干净" | 提示词没要求生活化小物 | 提示词里明确写"桌上必须有马克杯、便利贴、绿植、文件堆" |
| 中文变乱码方块 | 字体没嵌 | 换方舟/缝合像素字体 |
| 画面糊 | 用了非整数倍缩放 | 只允许 ×2 / ×3，检查 CSS 是否被 `max-width` 破坏 |
| **同一批资产风格互相不像** | 提示词太短、各写各的、没垫图、换 seed | 风格前缀统一 + 垫基准图 + 同批同 seed + 同会话生成；整批重出，别单张修 |
| **场景空旷"没人味"** | 提示词没点出生活化小物 | 字段 5 强制列出 3-5 件小物 |
| **UI 像玻璃拟态/现代扁平** | 没约束材质与描边 | 明确"磨砂塑料 + 1px 亮边 + 深棕描边 + 无渐变高光" |

## 1. 定位与目标

### 1.1 这是给谁做的

- **主要人群**：知乎站内的应届生、实习生、工作 1-3 年的职场新人。
- **手机场景**：通勤、午休、睡前躺着刷，单局 3-5 分钟，**单手可玩**。
- **PC 场景**：晚上在电脑前，知乎 Web 端正开着，愿意一次玩完一章、慢慢读知乎内容，**键鼠要能高效操作**。
- **两端同等优先**：不是"先在手机上能跑，PC 顺便"，而是**两端都要像为它专门做的**。PC 用户通常停留更久、读内容更认真，是知乎跳转率的主要来源，不能当附属品。
- **情绪目标**：先笑（手忙脚乱、同事毒舌）→ 再共情（第一次被否、功劳被抢）→ 最后被安慰（成长看得见）。

### 1.2 角色阵容：全员看山

**本作所有职场人物都是「刘看山」，只有主角是原版刘看山。**

这不是省成本的妥协，而是本作最重要的识别资产，有两层理由：

**设定层（推荐在第 10 章揭示）**：所有同事都是"另一个时间线上的刘看山"——林总是十年后的他，周岚是五年后的他，阿麦是同期做了不同选择的他，面试官是审视他的那个自己。**从头到尾，他一直在和各种版本的自己打交道。** 这让"从求职到成熟"这个主题真正落地：成长不是变成别人，而是成为其中一个自己。

**生产层**：一套骨架 + 一套差异参数 = 无限角色。招聘会人群、前台、保安、客户全部由同一骨架换色换配饰生成，**边际成本接近于零**，且天然风格统一。

| 角色 | 身份 | 一眼识别靠什么 |
|---|---|---|
| **刘看山（主角）** | 求职者 → 新人 → 成熟 | **最朴素**：白衬衫 + 知乎蓝领带，零配饰（朴素即识别） |
| **林总** | 总监 | 最大最宽 + 一侧耳朵缺角 + 眼镜 + 保温杯 |
| **周岚** | 带教上级 | 高瘦 + 琥珀围巾 + 抱着一叠文件 |
| **阿麦** | 同期好友 | 圆胖 + 暖橙卫衣 + 奶茶 |
| **韩策** | 技术同事 | 微驼背 + 深蓝卫衣 + 耳机 |
| **小鹿** | 校园方向同事 | 最小只 + 大耳朵 + 亮绿 + 拍立得 |
| **面试官 / HR** | 第一章对手戏 | 笔挺 + 藏青制服 + 工牌 |

**识别规范**（完整版见 `设计/美术圣经.md` §5.5）：差异必须按 **剪影 > 主色 > 道具** 的优先级花，每个角色至少靠两项区分；细节 ≥2px 才看得见；背景群像一律低饱和 + 简化五官，永远不抢主角注意力。
**三条可测试的验收线**：剪影测试（填纯黑缩到实际尺寸仍能认出 ≥5 个）、1 秒识别测试、主角突出测试。

> ✅ **已定：「不同时间线的刘看山」写进剧情**，暗线的揭示节奏见 §5.1。

### 1.3 与旧项目的关系

`liukanshan-intern-diary`（Godot 4.4，仿微信桌面，8 事件 3 结局）是**叙事骨架与合规实践的来源**，保留不删，作为对照。新项目继承它做对的三件事：

1. 分支与评分**人工写死**，AI 只做追问兜底；
2. 知乎来源**先人工校验再入缓存**，没有就明确不展示，绝不编造作者、标题、链接；
3. 随包嵌入开源中文字体，保证 Web 端中文不出豆腐块。

不继承的：Godot 引擎与仿微信 UI（新项目改用 Phaser + React，理由见 §12）。

## 2. 核心循环：三层闭环

```
        ┌──────────────── ⑦ 下一章 ────────────────┐
        ↓                                          │
  ① 对话抉择（读情报、做判断）                       │
        │  可插入技能卡 → 解锁隐藏选项 / 改写关卡规则   │
        ↓                                          │
  ② 协作关卡（3-5 分钟，手忙脚乱）                    │
        │  表现 → 星级                                     │
        ↓                                          │
  ③ 结算掉卡（技能卡入库、升级）  ────────────────────┘
        │
        ↓
  ④ 知乎知识卡（真实文章，点击跳转，回来解锁强化）
```

**设计论点**：三条链路必须互相供电，缺一条就退化成「看剧情 → 玩小游戏 → 看广告」的拼接体。

- **对话 → 关卡**：对话里拿到的情报、建立的信任、许下的承诺，直接改变关卡的**规则参数**（不是改分数）。
- **关卡 → 对话**：关卡星级决定你手上有几张、多强的技能卡，也就是**你说话有没有底气**。
- **知乎 → 两者**：读过的文章/问答解锁一张知识卡，知识卡既是游戏道具，也是叙事里"我学到了"的物证。入口是**常驻固定按钮**，玩家想看才点，不点不出现（详见 §10）。

## 3. 设计支柱（所有取舍以此为准）

1. **手忙脚乱但不惩罚**：失败推进剧情、解锁"狼狈卡"，而不是 GAME OVER。
2. **协作不能省**：队友必须会帮忙、也会掉链子，这是胡闹厨房的灵魂。
3. **选择要有代价**：没有"三个选项里一个是正确答案"，只有不同代价。
4. **双端一等公民**：PC 与手机同等优先。同一套游戏逻辑与内容，两套输入与布局适配层；**任何一端都不许是"凑合能玩"**。
5. **内容不注水**：知乎文章必须真、可点、可验证；评分与观点文案全部人工写死。
6. **一眼认人**：全员都是刘看山，但每个角色必须靠**剪影 + 主色 + 道具**中的至少两项一眼分清；主角永远是原版、最朴素、最显眼。

## 4. 深度层：向《星露谷物语》借的四个系统

这是回应「设计太简单」的关键——星露谷的可玩深度不在种地，而在**四层系统叠在一个循环上**。我们把它的四层结构搬到职场：

| 星露谷系统 | 本作对应 | 作用 | v1 是否做 |
|---|---|---|---|
| **四季变换**（色调、作物、村民对话全变） | **职场四季**：春=求职 / 夏=高强度融入 / 秋=独立承担 / 冬=低谷与选择 | 用极低的成本（光照与调色板预设）换巨大的"世界在变"的感受 | ✅ 必做 |
| **体力条**（熬夜会第二天废掉） | **精力条**：关卡与对话共享；加班能临时提升产出，但降低次日状态 | 让"要不要拼"成为真实取舍，把章节串成资源管理 | ⏳ **M3 上线（已定）** |
| **村民好感度**（独立好感、影响事件） | **同事好感度**：林总 / 周岚 / 阿麦 三人独立（韩策、小鹿后续加） | 决定关卡里谁来帮你、对话里谁替你说话、结局走向 | ⏳ **M3 上线，先做 3 人（已定）** |
| **节日与集市** | **年会 / 团建 / 客户答谢会**：特殊关卡 + 特殊掉落 | 章节节奏的调剂与高潮 | ⏳ 选做 2 个 |
| **博物馆图鉴** | **职场观察笔记**：收集到的知乎知识卡可翻阅 | 内容消费闭环 + 回访动机 | ✅ 做轻量版 |

**四季的具体表现**（几乎零成本、观感提升最大）：

| 季节 | 章节 | 光照预设 | 调色偏置 | 环境细节 |
|---|---|---|---|---|
| 春 | 1-2 | 冷白晨光偏亮 | 偏青绿 | 窗台绿植、招聘会彩旗 |
| 夏 | 3-5 | 强烈顶光、高对比 | 偏橙黄 | 空调外机、风扇、冰咖啡 |
| 秋 | 6-8 | 暖金斜光 | 偏琥珀 | 落叶、加班夜的台灯 |
| 冬 | 9-10 | 冷蓝低照度 | 偏灰蓝 | 暖气片、窗外雪、年终奖信封 |

> 实现方式：Phaser 4 的 `lights.setAmbientColor()` + 相机 `postFX`/Filter 的 `ColorMatrix`，一套参数四个预设，美术只需画一次场景。**这是性价比最高的一项深度**。

## 5. 十章结构

| 章 | 章名 | 职场阶段 | 核心情绪 | 对话主题 | 关卡主机制 | 知乎内容主题 |
|---|---|---|---|---|---|---|
| 1 | 投出去的第 47 份简历 | 求职 | 焦虑、硬撑 | 自我定位、岗位选择 | **收集与交付**（招聘会冲刺） | 应届生第一份工作怎么选、简历怎么写 |
| 2 | 面试间的三分钟 | 求职 | 紧张、被审视 | 不会的问题怎么答 | **顺序与时机**（面试问答接力） | 面试技巧、群面、HR 会问什么 |
| 3 | 入职第一天 | 入场 | 拘谨、被善意接住 | 自我介绍、边界初立 | **收集与交付**（装电脑/认人/物资归位） | 新人第一天做什么、职场礼仪 |
| 4 | 群里的第一句话 | 融入 | 想被接纳 | 发言分寸、群聊礼仪 | **并发与配比**（同时满足三个同事） | 职场沟通、如何请教别人 |
| 5 | 别把时间都给出去 | 融入 | 委屈、学会说不 | 拒绝、协调 deadline | **顺序与时机**（双线任务） | 职场边界感、怎么拒绝同事 |
| 6 | 下午三点的那句「年轻人喜欢什么」 | 承担 | 困惑到清晰 | 需求澄清、向上沟通 | **并发与配比**（需求拆解流水线） | 需求沟通、向上管理 |
| 7 | 第一次独立提案 | 承担 | 兴奋、孤军 | 汇报结构、展示成果 | **收集与交付**（材料赶制 + 现场答疑） | 提案与汇报、PPT 怎么做 |
| 8 | 方案被否的那天 | 危机 | 挫败、止损 | 复盘、承担 | **顺序与时机**（返工与止损） | 复盘方法、如何面对失败 |
| 9 | 功劳与署名 | 立场 | 愤怒、原则 | 公正、团队、争取 | **并发与配比**（贡献分配） | 团队协作、署名与职场公正 |
| 10 | 转正，或者离开 | 成熟 | 释然、选择 | 职业规划、长期主义 | **综合关**（前三机制随机组合） | 职业规划、要不要跳槽 |

**节奏设计**：每章 = 对话（2-3 个抉择节点）+ 关卡（1 局，3-5 分钟）+ 知乎知识卡（4 篇）+ 结算。第 5、8 章为情绪低谷，第 7、10 章为高潮。

**结局（v1 只做 2 个，已定）**

判定顺序如下，**「转向新领域」优先判定**（它更特殊，不该被稳健路线吃掉）：

| 结局 | 判定条件 | 情绪落点 |
|---|---|---|
| **转向新领域** | 成长 ≥ 70% 且 信任 < 50% | 他能力长起来了，但没在这家公司找到归属——于是他去做更想做的事。不是失败，是选择。 |
| **转正留任**（兜底） | 其余情况；若 信任 < 40%，启用「勉强的转正」文案变体 | 稳，但心里清楚还有账没算完。 |

> 原设想的「跳级升职」「结束实习」两个结局**保留为 M4 后的扩展**，v1 不做——两个结局质量做扎实，胜过四个都单薄。

### 5.1 暗线：全员看山的三次揭示（已定写进剧情）

**设定**：公司里每一个人都是「另一个时间线上的刘看山」。主线从头到尾，其实是**他在和各种版本的自己打交道**。

**揭示节奏（不能一次说破，也不能一直不说）**

| 章 | 手法 | 具体做法 |
|---|---|---|
| 1 | 埋一个细节 | 面试官笑起来的弧度和自己一模一样——**不解释，不给镜头强调** |
| 3 | 再埋一个物件 | 林总桌上那只保温杯，和自己家里那只是同款、同一处磕痕 |
| 5 | 半明示 | 周岚说"我当年也是这么过来的"，说完自己也愣了一下 |
| 7 | 隐喻 | 提案前他在电梯镜子里整理衣领，镜中人穿着林总那件深灰外套 |
| 9 | 逼近明示 | 阿麦："咱俩其实是一路人，只是在某个岔口选了不一样的走法。" |
| **10** | **正式揭示** | 答辩结束，林总把保温杯推给他——**杯子上刻的是他的名字**。全员看山的设定在此落地 |

**与结局的呼应**（两个结局都是"成为哪一个自己"，没有输家）

- **转向新领域**：他成了另一种自己——能力长起来了，但没在这里找到归属，于是去做更想做的事。
- **转正留任**：他成了这里的自己——选择留下，并清楚还有哪些账没算完。

**写作纪律**：暗线**不参与解谜、不加操作负担**，只做情绪与回味。玩家全程可以完全没意识到，直到第 10 章被那行刻字击中——**这才是好暗线该有的样子**。

## 6. 技能卡系统（完整规则）

### 6.1 来源

| 来源 | 规则 |
|---|---|
| 开局赠送 | 第一章送 1 张「不懂就问」，同时充当教学 |
| 关卡评级 | C 无掉落 / B 得 1 张 / A 得 1 张 + 1 次升级 / S 得新卡 + 升级 + 隐藏卡 |
| 防刷 | 每关只有**首次**评级掉落，重玩不计 |
| 保底 | 剧情关键节点必送，保证关卡打不好也不会卡住 |

### 6.2 使用规则

- 对话**大部分抉择不需要卡**，只有带「卡槽」标记的关键抉择可插 **1 张**。
- 每张卡**每章限用 1 次**。
- 三类效果：
  1. **解锁隐藏选项**（本不出现的第 4 个选项）
  2. **强化已有选项**（+1 变 +2，或额外拿一条情报）
  3. **改写下一关规则**（例如把"不知道岗位匹配关系"变成"关卡内直接显示"）
- **用卡不等于选对**：卡只是多一种解法，判断本身仍由玩家负责。这条是设计底线。

### 6.3 属性与卡池预算

- **类型**：提问 / 举证 / 共情 / 拒绝 / 复盘 / 幽默
- **稀有度**：普通 → 熟练 → 精通（升级靠评级，升级改变数值而非换卡）
- **总量**：10 章共 22-26 张，每章新增约 2 张，第一章 3 张（1 送 + 2 掉）

### 6.4 分数与奖励：卡是靠分数挣的

每局结束先算一个**明确的分数**，再由分数定评级、由评级定掉卡。分数必须可见、可解释，玩家要知道自己差在哪。

```
分数 = 交付数 × 100 + 剩余秒数 × 3 + 最长连击 × 20 − 失误次数 × 40
```

| 评级 | 分数线 | 技能卡奖励 |
|---|---|---|
| **S** | ≥ 900 | 1 张新卡 + 该卡**直接升为「熟练」** + 1 张**隐藏卡**（本章最强卡，只在 S 出现） |
| **A** | ≥ 780 | 1 张新卡 + 1 次升级机会（可指定任意已有卡升级） |
| **B** | ≥ 640 | 1 张新卡 |
| **C** | < 640 | 不掉战力卡，改为解锁 1 张**「狼狈卡」**——叙事收集品，可在观察笔记里翻阅，不参与抉择 |

补充规则：

- **只有首次评级掉落**，重玩不计卡，但会**刷新最高分**并记进成长档案。
- 结算页必须逐项列出分数构成（哪几项拿了多少、失误扣了多少），这是玩家愿意重打的唯一理由。
- 分数上限刻意留出余量：满额交付 + 40 秒余量 + 无失误 ≈ 1095 分，**S 线 900 是"打得漂亮"而不是"打得刚好"**。

## 7. 评价与结算

### 7.1 双轨评价

- **关卡轨**：星级 S/A/B/C，只看关卡表现（交付数、剩余时间、无谓失误），决定掉卡。
- **人物轨**：信任 / 团队 / 成长 三项，跨章累积，只由对话抉择改变，决定结局与部分对话选项。

**为什么分开**：关卡打得好不该让人物关系变好——那是两回事，分开才让"你是个什么的人"这个问题真正成立。

### 7.2 每次结算的四块内容

1. 关卡评级 + **分数构成明细**（哪几项拿了多少、失误扣了多少）
2. 掉落的技能卡（带一句风味文案；升级/隐藏卡要单独高亮）
3. 三项评价的变化（明确显示哪一句选择导致了哪一项变化）
4. **知乎内容入口**（核心必读 1 + 延伸 3）+ **生成分享图**

### 7.3 分享图规范（成长档案，已定要做）

分享图是知乎站内传播的钩子，必须做，但必须**干净、不骚扰、不自动发帖**。

#### 两个版本

| 版本 | 时机 | 尺寸 | 内容 |
|---|---|---|---|
| **单局版** | 每局结算（M2 起） | 1080×1440 竖版（适合知乎 App 发图） | 章节名 + 评级大字 + 分数构成 + 掉落的技能卡 + 一句人工写死的感慨文案 + 底部标识「刘看山职场记 · 知乎」 |
| **成长档案版** | 每章结算 / 通关（M3 起） | 1080×1920 长图 | 十章进度条 + 三项评价条形图 + 卡池收集度 + 各章最高分 + 结局 |

#### 规则

- **文案人工写死**：按评级从预写池里选一句（例如 A 级："节奏稳，只有几份简历没能赶上。"），**绝不让 AI 现编**。
- **评价必须真实**：图上所有数字都来自存档，不美化、不伪造。
- **不采集隐私**：不出现玩家真实姓名、账号、头像；只有游戏内数据。
- **不做自动分享**：只提供两个按钮——「保存图片」与「复制文案 + 打开知乎」，剩下由玩家自己决定。**不弹窗、不强制、不诱导**。
- **知乎标识合规**：刘看山与知乎字样的使用遵循授权范围。

#### 技术实现

客户端 Canvas 2D 合成（`canvas.toBlob` 导出 PNG），像素字体 + 像素边框，**不额外增加生图素材负担**——分享图用已有素材（卡牌框、评级徽章、装饰便利贴）拼装即可，另需 3-5 张装饰元素（胶带、便利贴、咖啡渍）。

#### 分享素材清单（进提示词包）

`界面_分享图外框.png`（外框）、`ui_rating_badge_S/A/B/C.png`（评级徽章四张）、`道具_分享图_胶带.png`（胶带）、`道具_分享图_便利贴.png`（便利贴）、`道具_分享图_咖啡渍.png`（咖啡渍）。

## 8. 关卡设计：三个机制循环复用十章

| 循环 | 机制原型 | 用在哪 | 学习成本 |
|---|---|---|---|
| **A 收集与交付** | 取件 → 加工 → 交付，订单队列 + 时限 | 第 1、3、7 章 | 最低，教学关用它 |
| **B 顺序与时机** | 步骤有依赖顺序，错序要返工；窗口期稍纵即逝 | 第 2、5、8 章 | 中 |
| **C 并发与配比** | 多需求同时到达，资源（人手/工位/精力）有限，要配比 | 第 4、6、9 章 | 最高 |

**修饰器**（每章叠一个，制造变化）：

- 地形变化（办公室搬工位 / 远程办公 / 跨楼层）
- 干扰事件（需求变更、投递口关闭、邮件爆炸）
- 多人协作（队友会帮忙也会掉链子）
- 精力惩罚（前一晚熬夜 → 移速与加工速度下降）

> 结论：十章不需要十个不同玩法，只需要三个机制 × 四个修饰。这是**能在预算内做完十章的唯一办法**。

## 9. 对话系统

### 9.1 节点结构

每个对话节点 = 场景描述 + 1 段 NPC 消息序列 + 1 个抉择（2-4 个选项）+ 可选的卡槽。

```
节点: { id, 章节, 场景, 消息[], 抉择: { 提示, 选项[]: { 文案, 代价, 效果, 前置条件 }, 卡槽?: { 接受类型[], 限 1 张 } } }
```

### 9.2 「代价」而不是「对错」

每个选项同时给出**收益与代价**，例如：

- 「先追问目标、受众和交付形式」→ 成长 +2，但**消耗 1 点精力**，且回答时间被 NPC 记一笔"想得太多"
- 「先做一版再确认」→ 专业 +1，但关卡里会多一个"需求变更"干扰

### 9.3 AI 的边界（硬约束）

| AI 可以做 | AI 绝对不做 |
|---|---|
| NPC 自由追问的一句话回应 | 决定分支结果 |
| 把知乎摘要改写成一句提示 | 编造作者、标题、链接、数据 |
| 玩家打字提问时给一个思考角度 | 输出评分、评价或结局 |

## 10. 知乎内容接入

### 10.0 设计红线：这不是广告位

先把"不做"写死，避免后面被人当成流量位改坏：

| ❌ 绝对不做 | ✅ 替代做法 |
|---|---|
| 开屏、插屏、自动弹窗 | 只在**固定位置**出现，玩家不点就什么都不出现 |
| 遮挡操作区的浮层 | 入口固定在结算页的固定区块 + 关卡内右下角的常驻按钮 |
| 打断对话或关卡的弹窗 | 关卡中只有按钮亮起小红点，**绝不弹出内容** |
| 伪装成系统提示的推广文案 | 标题直白写「知乎上关于这一天的讨论」 |
| 第三方广告、联盟链接 | 只跳知乎站内原地址 |

**一句话**：内容是被玩家"拿来用"的工具，不是被推给玩家的广告。

### 10.1 触发时机：每局完成后都会检索

- **每完成一局关卡**（无论 S 还是 C）→ 立刻按该章关键词检索知乎内容。
- **失败也展示**，但关键词换成"失败原因"（例如"投递口关闭导致没交完"→ 检索「职场 突发状况 时间管理」）。失败时更需要被安慰，这是情绪设计的一部分。
- 对话节点结束也会检索一次，关键词是该抉择的主题（例如"拒绝同事"）。

### 10.2 内容类型：文章与问答两类

| 类型 | 展示字段 |
|---|---|
| **知乎文章**（zhuanlan） | 标题、作者、专栏名、发布时间、赞同·评论数、摘要/节选、话题标签、配图（官方字段） |
| **知乎问答**（question/answer） | 问题标题、回答者、作者一句话简介、发布时间、赞同·评论数、回答节选、问题关注数 |

问答类对职场主题更贴——**每章至少保证 2 条真问答**，因为"别人的同类经历"比"方法论文章"更能接住情绪。

### 10.3 入口 UI：一个固定按钮，三步展开

```
① 常驻按钮（一直在，不挡操作）
   位置：关卡内右下角 / 结算页固定区块
   状态：默认灰 → 有内容时亮起 + 小红点(数量)
   ↓ 玩家主动点击
② 内容列表（从右侧滑入的 DOM 面板，不覆盖操作区）
   卡片：类型徽标(文章/问答) + 标题 + 作者 + 赞同数
   ↓ 玩家点击某张卡
③ 详情页（整页 DOM，可返回）
   作者区：头像 + 昵称 + 一句话简介 + 认证信息(官方有才显示)
   正文区：标题 + 摘要/官方返回的节选 + 话题标签 + 配图
   数据区：赞同 / 评论 / 发布时间
   底部固定按钮：「去知乎看原文」→ 新标签打开原地址
```

三条硬约束：

1. **位置固定**成 HTML 组件，不随关卡状态漂移，不用随机位置。
2. **永不自动展开**，只有点击才打开；打开后可随时返回，返回后关卡状态不受影响（关卡会自动暂停）。
3. **未通过校验的内容一律不显示**，宁可按钮是灰的，也不放凑数的东西。

### 10.4 内容生产流程（每章 **核心必读 1 + 延伸 3** = 4 篇，共 40 篇，已定）

**配比含义（这是设计，不只是数量）：**

| 位置 | 数量 | 作用 | 与机制的关系 |
|---|---|---|---|
| **核心必读** | 每章 1 篇 | 直接回应本章那个抉择困境的那一篇 | **读完解锁对应的技能卡强化**（内容消费 → 游戏收益） |
| **延伸** | 每章 3 篇 | 同一主题的不同角度（方法论 / 过来人经历 / 行业视角） | 纯阅读与收藏，收进"职场观察笔记"图鉴 |

生产步骤：

1. 用官方 API/CLI 按章节关键词检索候选（文章 + 问答各取若干）
2. **人工校验**：标题、作者、赞同数、是否真的回答了这个问题、是否夹带广告
3. 落成 JSON 缓存（只存**官方字段**）：
   `{ 类型, 位置(核心/延伸), 标题, 作者昵称, 作者头像, 一句话简介, 认证, 摘要/节选, 赞同数, 评论数, 发布时间, 话题标签, 原链接, 抓取时间, 校验人 }`
4. 线上**只展示官方返回的摘要/节选 + 跳转**；正文不在我们这里缓存、不转载、不改写。

> ⚠️ **诚实的边界**：如果官方接口只给摘要，那我们能展示的"详细内容"就是**标题 + 完整作者信息 + 摘要/节选 + 互动数据 + 话题标签 + 配图**，然后再跳转去知乎看全文。**不抓正文、不重排、不搬运**——这是合规底线，也是长期能活的前提。若赛事提供了授权的内容接口，再把正文展示纳入。

### 10.5 合规红线

- 没有校验过的来源 → **明确不展示**，绝不用 AI 补写
- 作者资料只取官方字段，缺失就不显示（不猜、不拼、不生成头像）
- 刘看山是知乎官方 IP，使用范围需按赛事/授权要求确认
- 埋点只上报"点开了哪一篇、是否跳转成功"，不采集玩家个人信息

### 10.6 与游戏机制的咬合

- **读完 = 解锁强化**：在详情页停留到底部并点击跳转，回来时该知识点标记为"已读"，解锁对应的知识卡强化（让内容消费真的有游戏收益，而不是纯展示）。
- **观察笔记**：已读内容收进"职场观察笔记"图鉴，可随时翻阅，这是回访动机。

## 12. 技术架构（已验证，不是设想）

### 12.1 双端适配规范（PC 与手机同等优先）

**原则：一份游戏逻辑，两套输入与布局。适配层只做"翻译"，不复制玩法。**

#### 输入层（两端都必须完整可用）

| 操作 | PC | 手机 |
|---|---|---|
| 移动 | `WASD` / 方向键 | 左侧虚拟摇杆（拖拽区，不需要精确点击） |
| 移动（备选） | 鼠标左键点击地面 → 寻路过去 | 点击地面 → 寻路过去（**同一套寻路代码**） |
| 交互 | `空格` / `E` / 鼠标左键点工位 | 右下角大按钮（拇指区） |
| 暂停 | `Esc` | 屏幕右上角固定按钮 |
| 对话选项 | 数字键 `1-4` + 鼠标点击 | 直接点选项 |
| 插卡 | `Tab` 打开卡槽 + 数字键选择 + 鼠标点击 | 点卡槽按钮 |
| 跳过对话 | `空格` / 鼠标连点 | 双击 / 长按 |

- **必须实现"点击寻路"**：它同时解决手机操作和 PC 鼠标操作，是性价比最高的输入方案。关卡内的 BFS 寻路逻辑（灰盒原型里已经写过一版）直接复用。
- **悬停（hover）只在 PC 生效**：`@media (hover: hover)` 判断，手机不做 hover 反馈。
- 键盘快捷键要在 UI 上**可见地提示**（按钮上角标 `1` `2` `3` `Esc`），PC 用户不用猜。

#### 布局层（用足各自的屏幕，而不是互相将就）

| 区域 | PC（宽屏） | 手机（竖屏） |
|---|---|---|
| 游戏画布 | 横版 512×288，居中整数倍放大（1080p 用 ×3 = 1536×864） | 竖版 288×512，×1 或 ×2 整数倍 |
| **HUD** | **放在画布外的黑边区域**（左右侧栏），完全不遮挡游戏 | 上下两条窄栏（覆盖画布 <45%） |
| 知乎内容面板 | **右侧固定 380-420px 侧栏，与游戏并排**，不遮不弹 | 全屏页面式，可返回 |
| 对话框 / 卡牌 | 居中模态，宽度上限 640px（避免大屏上一行 40 个字） | 底部抽屉式 |
| 输入 | 键盘 + 鼠标（含点击寻路） | 虚拟摇杆 + 拇指区大按钮 + 点击寻路 |
| 字号 | DOM UI 用设备像素（不随像素缩放），正文 ≥ 14px | 正文 ≥ 15px，按钮触控区 ≥ 44×44px |

> **关键决策：不因 PC 提高内部分辨率。** 内部分辨率只有横竖两种固定值，都是像素完美与素材网格的前提。PC 的优势用在**外围**——黑边区放 HUD、右侧放知乎内容、键鼠提操作效率。

#### 美术与渲染底层：原生双朝向（已定，不靠旋转、不靠拉伸）

**核心原理一句话：瓦片是正方形的，而两种内部分辨率都是 32 的整数倍。**

| 朝向 | 内部分辨率 | 瓦片视野 | 用在哪 |
|---|---|---|---|
| **横** | 512×288 | 16×9 | PC、手机横屏 |
| **竖** | 288×512 | 9×16 | 手机竖屏 |

因为两者都能被 32 整除，所以：

- **同一套 32×32 素材、同一条像素完美规则、同一条渲染管线**——不需要为竖屏另画一套素材，不需要旋转画布，也不需要接受非整数缩放。
- 相机只是"看同一个世界的不同窗口"，世界本身不变。
- 竖屏 390×844 实测：288×512 能以 **×1 整数倍**完整放入（可用区 362×816）；而旧的横版画幅 512×288 只能 ×0.707，会出摩尔纹。

#### 关卡如何同时满足两种画幅（关键：不手工画两张图）

关卡**只 authoring 一次**，写成与朝向无关的**逻辑描述**：

```json
{
  "stationCount": 3,
  "route": "shelf → desk → bin",
  "obstacleDensity": 0.18,
  "interferenceTimeline": ["t=42s 投递口关闭 6s", "t=90s 需求变更"],
  "quota": 8,
  "timeLimit": 150
}
```

再由**布局生成器**按朝向产出两种 tilemap：

| 朝向 | 工位排布 | 玩家动线 |
|---|---|---|
| 横版 16×9 | 工位横向铺开 | "一"字或"U"字 |
| 竖版 9×16 | 工位纵向叠放 | "丨"字或"S"形 |

规则、分数、掉落、对话、干扰事件**完全一致，只有空间排布不同**。这样"双端一等公民"的额外成本就从"每章多画一套地图"降到"写一次布局规则"，估算增量 **不到 10%**。

#### 已实测的双端数据（灰盒原型，自动断言）

| 视口 | 画布 | 缩放 | HUD 与画布 | 结论 |
|---|---|---|---|---|
| PC 1440×900 | 1024×576 @ (208,150) | **×2 整数倍** ✅ | 4 个面板，**重叠 0 个** ✅ | PC 布局成立：HUD 全在黑边 |
| 手机竖屏 390×844（**旧：横版画幅**） | 362×204 @ (14,300) | ×0.707 **非整数** ⚠️ | 窄栏在画布内，覆盖 34.6% | 这就是改成双朝向的原因 |
| 手机竖屏 390×844（**新：竖版画幅**） | 288×512 @ (51,146) | **×1 整数倍** ✅ | 窄栏移到画布外，覆盖 **4.7%** ✅ | **验证通过**：像素完美在竖屏保住了 |

> **竖版为什么固定 288×512（而不是按屏幕撑满）**：手机高宽比五花八门，如果竖版分辨率随设备变化，每台手机的关卡可见范围就不一样，布局生成器与关卡平衡会失控。固定 288×512 的代价是上下留黑边（390×844 上约占 146px + 186px），换来的是**所有手机看到完全相同的关卡**——而黑边正好拿来放 HUD 窄栏。**一致性优先于填满屏幕。**

⚠️ **由这次改造得出的一条硬结论**：竖屏下用**横版画幅**只能按 0.707 缩放，非整数倍会让像素出现不均匀的粗细（摩尔纹）。解决办法不是提示转屏、也不是拉伸，而是**让美术与渲染底层原生支持双朝向**——正方形瓦片 + 两种 32 整数倍的内部分辨率 + 布局生成器。详见上一节。

#### 性能与画质分层

- 默认两端同一套资源与参数；PC 上可额外开启（自动检测 + 可关闭）：Bloom、更远的光照半径、更高帧率上限。
- 手机默认关掉高开销滤波器，保证 60fps 优先。
- 4K/超宽屏：整数倍缩放 + 居中留边，禁止拉伸铺满。

#### 双端测试要求（进验收）

- 每次改动必须在**两种视口**下各跑一遍自检脚本：`1440×900`（PC）与 `390×844`（手机竖屏）。
- 自检脚本要能覆盖：键盘输入路径、点击寻路路径、触控按钮路径（用 CDP 触摸事件模拟）。
- 硬性检查项：**HUD 不遮挡可交互区域**、按钮触控区 ≥44px、无横向滚动、画布为整数倍。

### 12.2 架构图

```
浏览器
├── React 层        对话 / 技能卡 / 知乎文章卡 / 结算 / 分享图（DOM 的强项）
├── Phaser 4 层     关卡：瓦片地图、物理、粒子、光照、滤镜、触摸输入
└── 桥               状态 Phaser → zustand → React；命令 React → 事件总线 → Phaser

Vercel
├── 静态资源        512×288 像素图集（PCT 格式）、章节 JSON
└── Serverless      知乎检索代理（密钥不下发）、点击埋点
```

**选型理由**：文章卡排版、跳转知乎、登录态、手机适配、站内传播这五件事都是 DOM 的强项，而关卡需要的瓦片/物理/粒子/光照 Phaser 4 全都内置。**DOM 做 UI 还额外买到一件事：同一套 React 组件能同时满足 PC 侧栏与手机全屏两种布局，只需 CSS 切换。**

### 12.3 已验证事实（灰盒原型实测，非文档推测）

- Phaser **4.2.1** 已发布并跑通；`make.tilemap({ data })` 可直接从二维数组建图，`TilemapLayer.setCollision([1,3])` 生效
- `createLayer(..., gpu=true)` 可得到 **TilemapGPULayer**（整层一次 draw call，手机友好）
- 光照是一行：`lights.enable()` + `lights.addLight()` + `sprite.setLighting(true)`
- 像素完美三件套有效：`pixelArt` + `roundPixels` + **整数倍 CSS 缩放**（实测 512×288 → ×2 无抖动）
- Phaser ↔ React 双向桥实测可用，无重复监听、无内存泄漏

### 12.4 数据驱动

章 / 对话节点 / 卡牌 / 关卡参数 / 知乎内容全部 JSON + zod 校验，代码只做解释器。这是低成本做完十章的前提，也是**双端共用同一份内容**的前提。

## 15. 验收标准（怎么算做得好）

1. **不看说明书能玩通第一章**（教学关的最低标准）
2. **一次对话能改变一次关卡规则**（双核互锁成立，玩家能感知到"因为我问了，所以现在能看见岗位匹配"）
3. **分数→卡→插卡形成动机闭环**（结算页能逐项解释分数构成；玩家会为了刷 S 拿隐藏卡而重打，但重打不掉卡）
4. **知乎内容入口 100% 可预测**：位置固定、不自动弹出、不遮挡操作；未校验内容宁可不显示
5. **知乎跳转率**（给知乎侧的硬指标：每章到达结算的人数 vs 点开详情并跳转的人数）
6. **手机单局不卡、不糊、不掉帧**
7. **素材风格一致性**：随机抽 10 张资产与风格基准图并排，色温 / 描边 / 细节密度三项全部一致
8. **双端同等可用**：同一章在 PC 用键鼠、在手机用触控都能完整通关；PC 上 HUD 不遮挡游戏区、知乎内容以侧栏并排；手机上无横向滚动、所有可点元素 ≥44×44px
9. **两种输入都要走通**：键盘/摇杆操作与点击寻路各能完成一次交付（自检脚本覆盖两条路径）
10. **两种朝向都是整数倍缩放**：PC 横版与手机竖屏各自的自检里，缩放倍率必须是整数（自动断言）

|---|---|

### 17.5 双端

| 规则 | 数值 |
|---|---|
| 内部分辨率 | 横版 512×288（16×9 瓦片）/ 竖版 288×512（9×16 瓦片），**两者都是 32 的整数倍**，两端各取其一 |
| 缩放 | 只允许整数倍（PC ×2/×3，手机竖屏 ×1/×2）；**任何朝向都不接受非整数缩放** |
| 关卡 | 只 authoring 一份逻辑描述，由**布局生成器**按朝向产出两版 tilemap，规则完全一致 |
| HUD | PC：画布外黑边；手机：紧凑浮层（覆盖 < 45%） |
| 知乎面板 | PC：右侧 380-420px 侧栏；手机：全屏页面 |
| 触控区 | ≥ 44×44px |
| 输入 | 键盘 / 摇杆 / **点击寻路**三条通路都要能用 |

### 17.6 合规

| 规则 | 要求 |
|---|---|
| 知乎内容 | 只展示官方字段摘要 + 跳转，不缓存/转载/改写正文 |
| 作者信息 | 只取官方字段，缺失就不显示（不猜不拼不生成头像） |
| AI 边界 | AI 不决定分支结果、不编造来源、不输出评分与结局 |
| 刘看山 IP | 使用范围按赛事/授权确认 |
| 分享图 | 不出现玩家真实身份信息，不自动发帖，文案人工写死 |
| 埋点 | 只记录"点开了哪篇、是否跳转成功"，不采集个人信息 |

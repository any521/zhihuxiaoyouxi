# 0. 通用规格与铁律

## 0.1 生成尺寸 → 成品尺寸 对照表

**先记住一句话：生成图缩到成品尺寸时，源图上的细节必须"够大"，否则缩完就糊。**

| 用途 | 成品尺寸 | 建议生成 | 缩放 | 源图细节最小宽度 |
|---|---|---|---|---|
| **瓦片材质** | 32×32 | **512×512** | ÷16 | **≥32 像素** |
| 地图家具 | 高 48×宽 48 | 1024×1024（3×3 网格） | ÷7 左右 | ≥16 像素 |
| 角色精灵 | 32×48 | 1024×1024（按网格） | ÷15 左右 | ≥12 像素 |
| 表情头像 | 96×96 | 1024×1024（2×2 网格） | ÷5 | ≥10 像素 |
| UI 九宫格 | 可拉伸 | 1024×1024（单件） | ÷3~4 | ≥6 像素 |
| 剧情插画 | 16:9 | 1920×1080 | ÷3.75 | — |

> ⚠️ **瓦片是唯一"缩 16 倍"的类别，所以它的提示词必须专门强调"粗纹理单元"。**
> 其他类别缩放倍数小，正常描述即可。

## 0.1b 生成尺寸只能用"标准比例"（踩坑记录）

**生图服务普遍只支持一小组标准比例。** 请求极端比例会失败——实测：

| 请求的尺寸 | 比例 | 结果 |
|---|---|---|
| 1024×1024 / 1024×768 / 1024×683 / 1024×1365 | 1:1 / 4:3 / 3:2 / 3:4 | ✅ 正常 |
| 1920×1080 | 16:9 | ✅ 正常 |
| **1024×256** | **4:1** | ❌ **502 Bad Gateway**（上游拒绝） |
| **640×128** | **5:1** | ❌ 同上 |

**规律**：**超过约 1.8:1（或反过来 0.56:1）的比例基本都不支持。**

> **两个错误的区分**：
> · **401 Unauthorized** = 鉴权问题（token 过期 / key 没带上），**与尺寸无关**，刷新登录即可
> · **502 Bad Gateway** = 上游服务拒绝或崩了，**如果是"只有某个尺寸失败、其他尺寸正常"，那就是尺寸不被支持**

### 需要极端比例的长条时怎么办

**不要直接请求长条尺寸**，改成这个两步法：

```
一、画在标准比例的画布正中：用 16:9（1920×1080），
    把长条横向放在画面正中，宽度约画布九成、高度约画布六分之一，
    上下留出大片纯品红
二、后处理裁出来：我们的工具会"自动裁到内容边界"，
    裁完就是一条长条，尺寸对不对都不影响请求
```

**这条已经用在**：移动端顶栏、移动端底栏、像素沙漏（10 帧拆成两张 5 帧）。

> 记住一句话：**请求的尺寸必须是服务商认识的，成品的尺寸由我们自己裁。**

## 0.2 垫图规则

| 类别 | 垫什么 | 权重 | 为什么 |
|---|---|---|---|
| **角色类** | 垫**官方三视图原图**（`美术/素材库/原图/01-主角/角色_刘看山_三视图.png`） | 0.60~0.65 | 保住五官与体型 |
| **其他角色** | 垫同类角色的**三视图**，或垫主角三视图 | 0.60 | 保证同族 |
| 场景 / 家具 / 小游戏道具 | 垫 `美术/素材库/原图/00-风格基准/参考_风格基准图.png` | 0.50~0.55 | 统一风格与色调 |
| **瓦片材质** | **不要垫图**（或权重 ≤0.35） | — | 垫图会把"物件"带进材质里 |
| UI 界面 | 垫风格基准图 | 0.50 | |
| 特效 | 垫风格基准图 | 0.50 | |

### ⚠️ 三条垫图铁律

1. **绝对不要垫"上一张 AI 生成的同类图"**——误差会累积。
   （真实教训：曾经拿上一版没画鼻子的角色图当垫图，结果新图连鼻子也丢了。）
2. **风格基准图 `参考_风格基准图.png` 的背景是纯黑**（实测 `#000000` 占 25.6%），不是品红。
   拿它垫**需要品红背景**的素材时，必须在提示词里**再强调一次"背景是纯净均匀的品红色 #FF00FF"**。
3. 角色类**永远垫官方三视图**，不垫任何 AI 图。

```

**命名格式**：`<类型>_<主题>_<内容>.png`
例：`瓦片_地面_办公地毯.png`、`界面_气泡_我方.png`、`角色_周岚_四表情.png`

**不合格的素材**直接移进 `原图/_废稿/`，并改名 `<原名>_废_<原因>.png`。

```

② 内容：画什么、几件、各自什么形态
③ 视角与构图：正俯视 / 平视，网格怎么排

⑥ 背景：纯净均匀的品红色 #FF00FF（要抠图的）或 无背景（材质）

## 0.5 三条必写排错句

**你的生图工具没有负面提示词栏，所以"不要什么"必须写成正面陈述 + 排错检查。**

每条提示词末尾至少加一句：

```
排错检查：如果画面里出现任何人物、动物或角色的形象，这张图就是错的，必须重画。
排错检查：如果出现任何文字、字母、数字、水印、签名、辅助线或网格线，这张图就是错的。
排错检查：如果不满足「只说这一件事」，这张图就是错的。
```

# 1. 第 0 批 · 瓦片重做（P0 · 最急）

## 1.1 现在的瓦片为什么难看

**诊断**：旧瓦片是从 1024×1024 的材质图缩到 **32×32**，**缩了 32 倍**。
源图上的细密绒线/颗粒被面积平均成糊状，再量化到 32 色板时，
相邻的糊像素被吸附到两个交替颜色上 → **变成规则的棋盘噪点**。

> **所以问题不在颜色，也不在"像素风不够"，而在两件事：**
> **① 纹理单元太小（被缩没了）；② 光照/明暗不均（平铺后出现格线）。**

## 1.2 瓦片的五条特殊要求（每条提示词都要写进去）

```
一、这是**纯材质**，画面里只有纹理本身，**没有任何物件、没有任何家具、没有任何人物**。
二、纹理单元必须**粗大清晰**：每束绒线、每块色斑、每条纹理的宽度**至少 32 像素**，
    整张图看起来像由大约 16×16 个大色块拼成，**不要细密的逐像素噪点**。
三、整张图**只用 3 到 4 种颜色**，同一种颜色必须是完全相同的色值。
四、**光照绝对均匀**：没有明暗渐变、没有中心亮四周暗、没有阴影、没有暗角。
五、**四条边都可以和自身的副本无缝拼接**：纹理一直延伸到画布边缘，边缘处不出现边框、描边、亮边或暗边。
```

- **比例/生成**：1:1 · **512×512**
- **成品**：32×32（÷16）
- **垫图**：不要垫（或 ≤0.35）
- **命名**：`原图/09-瓦片v2/瓦片_地面_办公地毯.png`
- **提示词**：

```
温暖手绘感的 16-bit 像素画，清晰的方块像素与锐利的像素边缘，纯粹的像素画风格。
cozy hand-painted 16-bit pixel art, crisp square pixels, pure 2D pixel art.

**光照绝对均匀**：没有明暗渐变、没有阴影、没有暗角；
**四条边都可以和自身的副本无缝拼接**：纹理一直延伸到画布边缘，边缘处不出现边框、描边、亮边或暗边；

**排错检查：如果纹理看起来是细密的沙子状噪点，而不是成束的粗绒线，这张图就是错的。**
**排错检查：如果画面有明暗渐变或中心发亮，这张图就是错的。**
```

- **注意**：缩到 32×32 后，每束绒线会变成约 2–3 像素，这是**对的**。如果生成图看起来"太抽象、不像地毯"，说明色块还不够粗，把"32 到 48 像素"改成"48 到 64 像素"再试。

# 10. 关于瓦片的一个备选方案（值得考虑）

**瓦片其实非常适合"程序生成"，而不是 AI 生成。**

理由：
- 程序生成**绝对无缝**（数学保证）
- **纹理单元大小完全可控**（想要 2px 就 2px）
- **色板绝对统一**（直接用 32 色板里那几色）
- 速度快、可批量出变体、不消耗生图额度

AI 生成擅长的是**"有内容的物件"**（家具、道具、角色、界面），
而**"材质"这类纯重复纹理**，程序生成的效果通常更好、更稳。

如果第 0 批的 AI 瓦片试出来还是不满意，可以让我写一个 `工具/生成瓦片.mjs`
（用 32 色板 + 简单噪声算法，20 分钟就能出 6 张绝对干净的瓦片）。
这一条只是备选，先按上面的提示词试 AI。

# AI 队友行走图 · 重新生成提示词（四方向 16 帧）

> **为什么要重做**：现在这张表**每帧的头朝向在变**（用户报"AI 队友一直回头/摆头"）。
> 实测确认是**素材问题**：程序侧已经改成"一行 4 帧原样播"（不做任何去重 ✗），
> **剩下的抖动只能靠重新出图解决** ✔

---

## 一、规格（**照这个出，别改**）

| 项 | 值 |
|---|---|
| 一张图 = | **128 × 192 像素**（4 列 × 4 行） |
| 单帧 = | **32 × 48 像素** |
| 行序 = | **第 1 行 朝下 / 第 2 行 朝上 / 第 3 行 朝左 / 第 4 行 朝右**（和主角那张**完全一致** ✔） |
| 每行帧数 = | **4 帧**（列 1→4 就是走路的一个循环） |
| 背景 = | **透明**（不要白底、不要任何底色/网格/文字/水印） |
| 风格 = | 像素画，32 色以内，无抗锯齿（放大后是硬方块） |
| 缩放 = | 角色在 32×48 里**贴底居中**，脚底留 1~2px |

## 二、垫图（**必须用**）

拿**已有的那张表**当垫图，只改动作、**不要改角色长相**：

美术/素材库/成品/角色动画/角色_小鹿_四方向行走16帧_32x48.png

> 权重（0.45）左右（"像这个角色，但动作按下面的要求重画"）

## 三、提示词（可直接复制）

```
像素画角色四方向行走图，一张 128×192 的精灵表，4 列 × 4 行，每格 32×48，
透明背景，32 色以内，无抗锯齿。

角色：白色北极狐同事（发型/服装/配色严格照垫图，不要改动长相和衣服）。
四行分别是：第1行朝下、第2行朝上、第3行朝左、第4行朝右。
每行 4 帧，是一个自然的走路循环（左脚前 → 中间 → 右脚前 → 中间）。

⚠️ 最关键的一条：**每一帧的头部朝向都必须和本行一致，头不要左右转动、不要回头**。
上半身（头、肩、躯干）在一行的 4 帧里**保持不动**，只让**双腿交替迈步**、
手臂（或狐狸尾巴）做很小的摆动。侧面两行的脸始终朝同一侧。
脚底贴齐每格底部，角色在格子里居中。

第 4 行（朝右）必须是第 3 行（朝左）的**水平镜像**，但两个方向都要各自朝向正确。

排错检查：如果同一行里 4 帧的头朝向有任何变化、或者看起来像在扭头看别处，
就是错的；如果四行的角色长相/配色和垫图不一致，也是错的；
如果出现背景色、网格线、文字、水印，也是错的。
```

## 四、拿到新图之后跑什么

```bash
# 1) 先把格式统一（AI 出图常是 JPEG 改名成 PNG 的 ✗）
node liukanshan-career/tools/修图格式.mjs <新图>

# 2) 修行走表：保证第 4 行是第 3 行的镜像（不然会"走两步回一次头"）
node 工具/修行走表.mjs <成品png> liukanshan-career/public/assets/map/chr_<谁>_walk.png

# 3) 接进游戏 + 体检
node 工具/接入地图素材.mjs
node liukanshan-career/tools/事件四验收.mjs     # 里面对"真行走动画"有断言
```

## 五、验收标准（量出来的）

- 贴进游戏后，**同一行内 4 帧的"头部区域像素差"应该都很小**（头不动 → 差异集中在腿）
  · 之前的表量出来是"每帧都在变"✗；重做后应该只有腿部在变 ✔
- `第 4 行 vs 第 3 行镜像` 的平均差应该是 **0.00**（`修行走表.mjs` 会自己保证 ✗）

## 附：这件事的教训（已经写进坑表）

**素材冗余/帧重复，要在"改素材"这一步解决，不要在运行时偷偷丢帧。**
我之前写了"按像素差去掉重复帧"的逻辑 ✗ —— 它把正常步态砍成了 2~3 帧，
播起来就是高频抖动 ✔（用户两次报"动画错乱"✗）。**路径是重新出图 ✗，不是运行时打补丁。**

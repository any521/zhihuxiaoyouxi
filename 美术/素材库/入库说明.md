# 美术素材库 · 刘看山职场记

生图产物统一放这里。**目录结构和文件名都不要自己改**——后处理与校验脚本都按这套规则读。

---

```

│   ├── 03-其他角色/           批次 3  学长 / 面试官 / 背景群像
│   ├── 04-场景/               批次 4  招聘会（横竖）/ 出租屋 / 办公室
│   ├── 05-瓦片/               批次 5  瓦片材质
│   ├── 06-道具/               批次 6  家具与道具
│   ├── 07-界面/               批次 7  界面组件
│   ├── 08-特效封面/           批次 8  特效 / 分享图 / 章节封面

```

**只往 `原图/` 里放东西。** `成品/` 是处理产物，不要手放。

---

## 2. 命名规范（全部中文）

| 类型 | 命名式 | 例子 |
|---|---|---|
| **生成原图**（一张大图含多组件/多帧） | `<类型>_<主题>_<内容>.png` | `角色_刘看山_设定总表.png` |
| **处理成品**（切片 / 九宫格 / 单精灵） | `<类型>_<场景>_<部位>_<变体>.png` | `瓦片_地板_地毯_01.png` |

**类型前缀只有这七个**：`角色_` · `背景_` · `瓦片_` · `道具_` · `界面_` · `特效_` · `参考_`

**硬规则**

1. **全部用中文命名，包括文件夹。**
2. 分词用下划线 `_`，不用空格、不用连字符。
3. 编号两位阿拉伯数字：`01` `02`。
4. 不加 `最终`、`修改版`、`v2`——重做就**覆盖原文件**，旧版丢 `原图/_废稿/`。
5. **文件名必须与 `素材清单.csv` 完全一致**，差一个字校验脚本就报"清单外文件"。

## 3. 入库流程（三步）

1. **生成** → 按 `美术/第一章-成品提示词.md` 里每条提示词上方标注的**比例、尺寸、垫图、文件名**设置工具。
2. **放文件** → 按 `素材清单.csv` 的「目录 + 文件名」放好，例如：
   ```
   原图/01-主角/角色_刘看山_设定总表.png
   原图/04-场景/背景_招聘会_横版.png
   ```
3. **校验** → 在项目根目录执行：
   ```powershell
   node 工具/检查素材.mjs
   ```
   它会告诉你：已就位多少张、缺哪些（按批次列）、**比例对不对**、分辨率是否低于标准、有没有命名写错的多余文件。

## 4. 比例与尺寸速查

| 比例 | 生成尺寸 | 用在哪 |
|---|---|---|
| **1:1** | 1024×1024 | 角色 / 道具 / 瓦片 / 界面组件 / 图标 / 特效（多帧用 2×2、3×2、3×3、4×4 网格排布） |
| **4:3** | 1024×768 | 知乎内容卡 |
| **3:4** | 1024×1365 | 卡牌框 / 分享图外框 |
| **16:9** | 1920×1080 · 1600×900 | 横版场景 / 横版封面 |
| **9:16** | 1080×1920 · 900×1600 | 竖版场景 / 竖版封面 |

**只用这五种比例。** 不要用 4:1、3:1 这类长条——多数工具不支持，而且会把每帧压得很小。

## 5. 放之前先自己过一遍（省返工）

**原图阶段只看这几条**（色数与噪点不在这一关验收——实测模型做不到，硬卡只会白费时间）：

- [ ] **视角对不对**（最重要）：场景是**正上方垂直俯视**（只看得到物体顶部），角色是**平视贴地**
- [ ] 构图：主体不顶到边缘，四周有留白
- [ ] 造型：角色结构正确（黑豆眼、白手掌、2 头身）、道具**齐备**（提示词里"必须出现"的都画了）
- [ ] 背景是**品红系纯色**（白狐绝对不能用白底，边缘会被吃掉）
- [ ] 画面里**没有文字、字母、数字、编号、水印**
- [ ] 描边是**深棕色**，不是纯黑；光从**左上 45°**，全场方向一致
- [ ] 与 `原图/00-风格基准/参考_风格基准图.png` **并排看**：色温 / 描边 / 细节密度三项一致

**成品阶段（转换后）才验收像素指标**：

```powershell
node 工具/转像素画.mjs "<原图路径>" "<成品路径>" --宽=256 --透明
node 工具/图片体检.mjs "<成品路径>"
```

| 指标 | 合格 | 优秀 |
|---|---|---|
| 颜色总数 | ≤ 512 | ≤ 64 |
| 孤立像素占比 | < 6% | < 2% |
| 横向同色游程众数 | ≥ 2px | 3-8px |
| 背景单色占比（需抠图的图） | > 90% | > 98% |

## 5.5 废稿处理（合格就放批次目录，不合格立刻移走）

**批次目录里只允许存在合格的图。** 不合格的立刻移到 `原图/_废稿/`，命名规则：

```
<原文件名>_废_<一句话原因>.png
```

例：
```
参考_风格基准图_废_多画了角色.png
角色_刘看山_设定总表_废_脸上没有大黑鼻子.png
```

**为什么要这么做**：批次目录是"当前有效资产"，混着废稿会让后续挑图、拼图集、统计进度全部出错；
而且垫图环节很容易顺手拿到一张废稿，**错误会顺着垫图链扩散**。

**为什么不删**：废稿是排查依据——同一张图反复出错时，回头看废稿能立刻看出"哪一版开始跑偏"，
也能用来对比提示词改动到底有没有效果。


**不合格的整批重出，不要单张修补**——单张修必然越修越花。废图丢 `原图/_废稿/`。
**脚本能救色数与噪点，救不了视角和构图**——那两条必须在原图阶段过。
